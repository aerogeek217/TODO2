# Layout edit mode

**The layout edit mode** (layout edit mode E1, reversing 11/08's no-arrange-mode; `workspace-store.editing`; desktop only — the phone has no way in, and narrowing the window to a phone's closes it): opened from **Edit layout…** in the open layout's tab menu and the picker (there is no button for it in the top bar), the palette's **Edit Layout**, the editable `edit-layout` shortcut (no keys by default) and **Edit layout** at the end of a cell's ⋯ / right-click menu (that cell selected, `selectedCellId`: an accent ring). Opening asks an open editor holding changes first, then closes every editor, the widget popup, the filtered-tasks panel and the snackbar. While it is on, `working` is a **draft** and `saved` the layout as stored: every structural edit (a card's menu, keys, corner and drags — cards, tabs, a strip's Numbers, tray chips — with the ghost, a slot's kinds, the rulers, dividers, a tab's ×) changes only the draft and is a step of **the mode's own undo**, and resizes and view state change only the draft — nothing is written. The top bar's contents give way to **the mode's bar** (`LayoutEditBar`: `Editing “X”`, the layouts' tabs disabled, the widget tray (`LayoutEditTray`, below), Undo, Redo, Cancel, Done; the focus on Done, and back where it was on leaving); Ctrl+Z / Ctrl+Y and the palette's Undo / Redo step the mode's stack and, with it empty, do nothing (never a task step behind it). The workspace is tinted under a faint dot grid with an accent outline (`--edit-*` tokens), each cell's content stays mounted but dims and takes no presses (each cell is a card: its surface under the content, its ⋯ and corner over it), and nothing moves.

**Done** commits the draft as one write and one undo step (`Edited layout “X”`, whose Undo brings back the lists it dropped through the usual run); with no change it just leaves.

**Cancel** asks nothing: the stored layout comes back and the snackbar offers `Layout changes discarded · Restore` (the draft and its undo steps back, the mode open again); the lists made in the session (`createListAndTab` records them) are deleted only once that offer is gone without Restore; till then — and in the mode, a list it made and then undid — no list chooser offers them (Copy from…, a Number's Follow a list: `workspace-store.listsHeldByEdit`, `hooks/use-held-lists`). Layout undo steps refuse meanwhile (`Finish editing the layout to undo: …`), as do a rename / hue / icon, Retry and the layouts' order.

**Leaving the layout** with changes — a layout switch (tabs, picker, palette, shortcut), Settings, an in-app route change, New / Duplicate / delete layout, Esc — asks Save / Discard / Keep editing (the mode is a layout-wide editor in `editor-leave`, asked only by `leaveLayout`, so a cell's split, merge or close inside the mode never questions it); with none it just leaves. A data replace closes it (`Edit layout closed: its changes weren’t saved.`); a reload or a closed tab drops the draft silently, and the next launch's prune deletes the lists it made.

**The rulers** (E2, `LayoutRulers`, mounted first in the table while the mode is on; `utils/layout-rulers`): grid items of the table itself, overlaid on the gutters and the cells' outer edges so no cell moves (16px strips; the card's ⋯ sits 16px down to clear the "+"s; a row ruler takes no part in sizing its row, `contain: size`, so a fit row keeps its height) (the workspace's top and bottom padding move into the table's scroller while the mode is on) — a ruler along the top of each column (A, B, C…; its share — a percent of the weighted columns, a fixed one's px — in its tooltip) and down the left of each row (1, 2, 3…, marked `fit` / `folded`), each a button (`Column B options`) opening its menu: Insert column left / right · Even all widths, or Insert row above / below · Collapse / Expand row (off while no filled cell lies only in it) · Even all heights, then **Remove column / row**, its line under it naming what goes where (`Status joins Tasks for… as a tab.`, `Notes moves into the row above.`, `The Numbers strip (Open and Overdue) joins Tasks: its Numbers become tabs.`). Only **major** tracks are lettered and numbered: a **sliver** — drawn under 24px (`SLIVER_PX`, the table's computed tracks) with no cell lying only in it, as a part line moved a few px leaves — gets an unlabelled tick — a pill in the ruler's strip on the sliver's start — whose menu offers Merge into A / B (`mergeTrackInto`). A **"+"** (a 20px disc in a 24px target — a larger one would cover the first tab of a strip along the strips) sits on every line between rulers and at both ends (`Insert row here`; the first row line's in the corner, the first column line's just right of it).

**A sliver and its two lines act as one line** (`layout-rulers.sliverRun`): one "+", just before the sliver, named by the majors around it (`Insert row between 1 and 2`); it — and a ruler's Insert above / below beside a sliver — merges the sliver away and inserts on the line left (`insertTrackAt`'s `through`), so a part line moved a few px no longer turns a full row into half a one.

**While a "+" is hovered the table makes room** (layout editor round two, concept A, 2026-11-19): it draws the layout the insert would leave (`workspace-store.structurePreview`, transient — never saved, never an undo step, cleared by every edit and by leaving the mode; `utils/structure-preview.structureProbe` runs the op on probe ids, `insert-preview.insertPreview`) — the new track's empty cells as solid accent slots (`data-preview-new`), the cards that grow across it outlined in the follow-up color with `stretches` (`data-preview-grew`), no dividers meanwhile — and the mode bar says it in the tray's place (`Row between 1 and 2 · Notes stretches across it · click to insert`, `layout-edit-preview-hint`); the "+" itself is pinned where the pointer found it while the table reflows under it (fixed, `data-pinned`; the table's other "+"s take no pointer meanwhile), so the preview never flickers; leaving it puts the table back. A click inserts a full row / column there and selects its first new cell.

**A "+" along every gutter**: hovering a divider in the mode shows a pill just beside its line (right of a column line, below a row line — the divider stays free to drag) that follows the pointer along it (`GutterPlus`, over `gutter-plus`'s context the table lends its dividers; it outlives the divider's leave by 250ms, time to move onto it); hovered it previews and clicked it inserts on that line (a sliver's run as the rulers' "+"). Rulers and "+"s are Tab stops in order (columns, then rows); Enter / Space opens a menu or inserts, Esc closes the menu with the focus back on its ruler. Every track action goes through `edit()` — a mode undo step on the draft (Even all is a size change: view state, as a divider's) —; the dividers are the mode's gutters.

**In the mode every cell is a card** (layout edit mode E3, `components/workspace/EditCard` + `edit-card-actions`): its **surface** (`data-edit-surface`, a Tab stop) lies under the card's dimmed content, which takes no presses (`data-edit-layer`), so a press anywhere on the card lands on it — a drag (past dnd-kit's 5px) moves the whole card through the drop model above, a short click selects it (`selectEditCell`, the accent ring, `data-edit-selected`) and **arms a move**: the mode bar's tray gives way to `Click a slot to move “X” there, a card to swap, or its tab bar to join it · Esc cancels`, and the next click on a slot moves the card there, on another card's middle swaps the two, on its tab area (its strip, a one-widget card's top band) joins them as tabs (near its edge it selects that card instead; on the armed card again, disarms) — the zones a drop reads — `workspace-store.tapEdit` over `utils/layout-edit-cards.tapOutcome`, WCAG 2.5.7's single-pointer way. A card's tabs (its strip's `role=tab`s, which still take presses) and a Numbers strip's Numbers (each slot a tab's drag, their insides inert) drag on their own to another card or slot, and a Number dropped in a strip's middle joins it.

**A card is a blueprint** (round two, concept A): its body stays mounted but hidden and `EditBlueprint` names it — its active widget's icon, name and kind, centred (on one line in a short card); a card of tabs keeps its live tab strip over it (its tabs drag, a drop there joins), a Numbers strip keeps its Numbers (each drags on its own; no blueprint) — unless the mode bar's **Content** toggle (an eye, `editing.showContent`, the session's only) shows the dimmed widgets as before. Over the content the card's chrome: its **label** (only with Content on: the widget's icon and name — shown on the card's hover, focus or selection; a strip's `N Numbers`; none over a tab strip — unless the strip is squeezed to its active tab with the title cut away, in a narrow card: then that tab's name, under the strip, `data-strip-squeezed`), its **⋯** (named **Cell layout**) and its **corner** (`data-edit-corner`) — the ⋯ and the corner shown on the card's hover, focus or selection (always on touch) —, all clear of the rulers' strips.

**The selected card's toolbar** (`EditCardToolbar`, fixed above the card, inside it under its header in the top row; frozen while a preview reflows the table; none while something is dragged): Split → and Split ↓ (each hovered, the table draws the split — `insert-preview.splitPreview`), Swap ▾ (every other card), Merge ▾ (the neighbours it makes a rectangle with; off with none) and Remove widget / Remove tab — each a step of the mode's undo.

**The card menu** (the ⋯, a right-click anywhere on the card, Enter on it; `cell-menu.editCardMenuEntries`, `EditCardMenu`): **Move to ▸** (every slot by its ruler name, `B4` — `layout-edit-cards.cellRulerName` over the rulers' `trackNames`, lent by the table through `layout-edit-view`), **Swap with ▸** (every other card by name, its place beside it; `swapCells`), **Join as tabs ▸** (the same cards: this card's tabs join it, the keys' way to a drop on its tab area), **Insert ▸** Row above / Row below / Column left / Column right (a full track on the card's edge line, as the rulers insert: `workspace-store.insertTrackBeside`, its first new cell selected — a card is where one looks for it) then Split this cell's New cell above / left / right / below, **Merge with ▸** (off, saying why, unless the two make a rectangle), **Stretch right** / **Stretch down** (one track, over empty slots only), then **Remove widget** (the card's active tab, its cell left a slot; **Remove tab** on a card of tabs) and **Close cell** (the absorb rule; `(N tabs)`).

**Stretch**: the corner dragged grows the card from its top-left over empty slots, track by track (a track once the pointer passes its middle, `trackReached` / `cornerArea`), and shrinking leaves slots; the table draws where it lands while it runs (`ws-stretch-ghost`, `Stretch · A2–B2`), Esc puts it back, the release stores it — `setCellArea` (`workspace-layout-ops`, valid only over the cell's own places and empty cells, which it absorbs or cuts into rectangles; the places it leaves become empty cells, cut the same way).

**The keys** on a card: the arrows move the selection (and the focus) to the card or slot beside it (`spatialNeighbour`: the one sharing the most of that edge), **Shift+arrow** stretches it one track from its bottom-right corner (right / down grow, left / up give one back — `stretchedArea`), **Alt+arrow** moves it onto the slot beside it or swaps it with the card there (`altMove`), Enter / Shift+F10 open its menu, Space is a tap, Delete / Backspace runs Remove widget on its active tab (its accessible name says so); the focus stays on what moved (`edit-focus.focusEditItem`, by `data-edit-focus`).

**An empty cell is a slot** (`EditSlot`): dashed, named by the rulers (`Empty slot B4`), a Tab stop (the arrows as a card's, Delete closes it), its close × kept; a click opens the widget kinds (`AddWidgetFlow`, Tasks / Insights, the new widget filling it — a List with its list through `createListAndTab`, whose ids the session records) — or, with a card armed, moves that card there.

**The tray** (`LayoutEditTray`, in the mode bar's `data-layout-edit-tray`): the common kinds as chips (List, Calendar, Notes, Number, Breakdown) and **More ›** with the rest; a chip dragged onto the workspace is a new widget's drag (`workspace-drag.beginNewWidgetDrag` → the page's drag state, source `{ type: 'new', kind }`, its own pointer-up drops it and Esc cancels it) — the drop model decides and the ghost labels it; a click adds the kind to the selected slot or card (`widget-hooks.addWidgetKindAt`, a Breakdown a Custom one). It scrolls sideways when the bar is narrow, so the bar never overflows. Outside the mode none of this is drawn.

**Drops in the mode** (on the draft; `utils/workspace-drop`, on the geometry `measureWorkspace` takes when a tab or cell drag starts — again while the table scrolls under it): the layout's left / right edge (24px inside; over a narrow edge cell's body no further than half of its own side split zone) inserts a column, its top / bottom edge (24px inside, reaching 16px past) a row; a cell's strip takes a tab at an index; a cell body splits on its outer 20 % (at most 120px) on each of its four sides — a cell with one widget has no strip, its whole card is its body, but in the mode its top band is its **tab area** (`workspace-drop.tabBand`: a header's height, at most 35 % of the card, where its label sits; measured only in the mode, `measure.cardTabArea`), which joins as a tab after its widget, the split-above zone lying below it — and in its middle a tab or a tray chip's widget joins as a tab while **a whole card swaps** with it (`{ kind: 'swap' }`: the two cells trade places whole, every tab with them); an empty cell (a slot) takes the drop — a tab or a tray chip's new widget fills it, and a whole card moves into it, the two swapping places (`movePanel` onto an empty cell is `swapCells`), so its old place is a slot and a move never grows a card over where it was.

**One ghost** (D26 board T, `dropGhost`, drawn by `DragOverlayLayer`) shows the result: the move run on a probe copy of the layout and the cell that ends up holding what is dragged placed from the drag-start geometry — a fit row of the result at the height the browser will draw it (`fitRowHeights`, widget feedback 2D: one that was a fit row its drawn height; a new one, or one the drop leaves holding only Numbers, the fit row its cells came from, else a Number's 58px), so the ghost is the landed cell also when a drop changes which rows fit —, labelled `Split Late · above`, `Insert row · full width`, `Insert column · full height`, `Add as tab` (`Add N tabs`), `Add to strip`, `Swap with “Tasks, Notes + 1”` (the other card by its name), onto a slot `Move here` (a card) or `Add here`; it fades in at each new spot (reduced motion: at once).

**Move / Copy to layout** (2026-11-18, `features/cross-layout-moves-2026-11-18`; desktop only): a widget's ⋯ / right-click has **Move to layout ›** and **Copy to layout ›** (that widget: a tab, a strip's Number), a card's menu in the mode **Move cell to layout ›** / **Copy cell to layout ›** (the whole cell, its active tab kept) — each the other layouts (the open one off, `this layout`) and **New layout…** (its name asked, `ui-store.requestLayout({ kind: 'new', transfer })`; Cancel deletes it again). A pick leaves the layout as any switch does (an open editor's question; in the mode, its draft's Save / Discard / Keep editing) and opens the target **in the layout edit mode with the widgets in hand** (`workspace-store.transferTo`, `LayoutEditSession.incoming`, `utils/layout-transfer`): the tray gives way to `Place “Errands” from “Main”: click a slot, a card to join it, or a +` (`a copy of “Errands”` for a copy), **At the bottom** joins the bar, and Done is off until they are placed. A slot takes them, a card (anywhere on it) joins them as its last tabs, a ruler's "+" inserts a track holding them, At the bottom a full-width row (`placeIncoming` → `workspace-layout-ops.placeIncomingTabs`, a step of the mode's undo); the draft may show the source's lists meanwhile (`edit()` lets `incomingListIds` through `foreignListRefs`).

**Done** writes both layouts in one transaction (`layoutRepository.transfer`): the target's draft, and for a move the source without them (`removeTabsKeepCell`: a lone widget's cell stays, empty); a carried list is **handed over** (the same list, re-owned) on a move whose source no longer names it, else **copied** with its manual order — always on a copy (`transferListPlan`) —; one undo step, `Moved “Errands” to “Second”` / `Copied …`, that undoes and redoes from either layout (`undoTransfer` / `redoTransfer` over `layoutRepository.untransfer`: copies deleted, kept for the redo; lists handed back; what the writes pruned restored; refused in the mode).

**Cancel** or Esc while they are still in hand goes back to the source, nothing written. Notes carry nothing (one global note), a Review widget's temporary filter stays behind, every other config and view state goes with the tab (a tab id the target already uses is renewed).
