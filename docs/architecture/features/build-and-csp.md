# Builds and the content security policy

**Builds + CSP** (a `<meta>` in `index.html`, first in its head, `base-uri 'none'; form-action 'none'` everywhere): the online build (`vite.config.ts`; `dist/index.html`) loads scripts from `./assets` only, so its `cdnFonts` plugin drops `script-src 'unsafe-inline'` (and adds Google Fonts) and `noInlineScripts` fails the build on any inline script. The offline single file (`vite.config.offline.ts`; `dist/todo2.html`) **makes no network request**: its own policy (`offlineCsp`) denies by default and names no `'self'` (on `file://` it would admit any `file:` URL, a UNC share's among them) — inline styles, `data:` images and fonts, no connect / frame / object / worker / media / manifest (the check-in dialog's message is a sandboxed `srcdoc` frame, which fetches nothing) — and allows its one inline script by its sha256 (`offlineScriptHash`, the build's last step, over the final text; the build fails on a second script or a mismatch); it sends no Referer and turns DNS prefetch off. The build then runs the **egress check** on the finished file (`offlineEgressCheck` → `scripts/offline-file.checkOfflineFile`): it fails on anything that loads, a `<!--` in its script text (after it a `<script` would make the browser read past the first `</script` the check stops at), a looser policy (a CSP directive named twice too: browsers enforce its first copy), no `no-referrer` / DNS-prefetch-off meta, a network API in the code (a navigation away — the location assigned or its `assign` / `replace`, `navigation.navigate`: no CSP directive stops one —; a reference to `window.open`, called or not; a resource hint's rel value, quoted anywhere in the script — the library hint code the app never calls is on its inert list) or a URL off its inert list (protocol-relative ones too, a dotless UNC `//host/share` among them) — each inert entry with its reason; ESLint bans the network APIs in `src/` (and navigating away — a location assignment, `location.assign` / `replace`, `navigation.navigate`, a form's submit, a link's or form's target in markup; the one link the app makes, a download's, takes `URL.createObjectURL(…)` directly —, and the HTML-parsing sinks — `innerHTML` / `outerHTML` writes, `insertAdjacentHTML`, `document.write`, `dangerouslySetInnerHTML`: nodes are built, never parsed from a string), and `e2e/built-csp.spec.ts` audits the file's requests through its main flows. The sync file, imports and exports go through the File System Access API, file inputs and downloads, which no fetch directive governs. Its icons are `data:` URLs too (SVG, the .ico's 16–64 px bitmaps, the 192 px PNG — `offlineIcons`) and it has no manifest link, so the file works alone from disk. Dev keeps `'unsafe-inline'` for the React refresh preamble
