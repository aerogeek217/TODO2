# Dismissing popovers and leaving editors

A change a popover shows either sticks or the user is warned. Esc or a click off saves what was typed (`FollowupPopover`, `SubtaskChecklist` in every host, `TaskNotePopover`; in the task editor the Status updates add line and + Add subtask line, which Esc leaves and the editor's close adds): each writes it in an unmount cleanup, so every way of closing is covered, and only a Cancel button drops it. Esc inside an inline edit — a subtask rename, a status entry — cancels that edit and leaves the popover or editor open. Text that can't be stored holds the close once, saying so; closing again drops it (a filter expression that doesn't read too: the first press outside its field, `ExpressionField`). Edit list and the widget editors (a Number's, a chart's, Created vs completed's) hold a copy until their Save, which writes it for good as one undo step (layouts and lists themselves have no Save: every other edit is stored at once): closing one with changes asks Save / Discard / Keep editing, and the press that asked goes no further; closing one with none just closes. The layout edit mode holds its draft the same way, as a layout-wide editor: only leaving the layout asks it (Save / Discard / Keep editing), never what is done inside it; its Cancel asks nothing and offers Restore instead. **Nothing leaves one with changes without that question** — one rule, `stores/editor-leave` (each registers through `hooks/use-editor-leave` while mounted): whatever would close it or take its subject off the screen from outside asks first and then carries on — Save or Discard, then it does what was asked; Keep editing, nothing changes: opening Settings (the gear, `G S`, the palette, the storage pill — `ui-store.openSettings`), opening another editor (`openListEditor` / `openNumberEditor` / a chart's or Created vs completed's — another list's Edit list opens once this one was saved or discarded; `widget-hooks.openEditList` asks before it shows the tab; one editor at a time, whatever its kind: `editor-leave.openOneEditor` closes any other, and `closeOpenEditors` is the one roster Settings, the widget popup and a data replace close them through), adding a widget (`widget-hooks.addTabToCell` / `AddWidgetFlow`: a ⋯'s Add widget as tab ›, an empty cell's kinds, the strip's `+`, the palette's Add Widget ›), opening the layout edit mode (`workspace-store.enterEdit`, which then closes every editor), **whatever in a cell can take a widget off the screen** (`FilledCell`, `cell-menu`, the phone's cell: a tab switched — a click, Enter, the arrow keys, the `+N` menu — or closed, Collapse / Expand row, the menu's Remove widget and Change widget — from the keys or a menu, a press elsewhere having asked already; the one press that carries on is a tab's: held by the question, it is made again once the answer is Save or Discard (`use-editor-leave.carryOnAfterLeave`), so a click switches tabs as the keys do, with one question; after it the focus is on the new tab), opening an editor on a tab out of sight (`widget-hooks.openBeside`, every editor's way in), closing the widget popup over an editor opened from it (its ×, its scrim, Esc) and a Review jump that would close it, a layout switch from the tabs, the picker, the palette or a shortcut, New / Duplicate layout, deleting the open layout (`workspace-store.load` / `createLayout` / `duplicateLayout` / `delete`), and an in-app route change — the phone's tab bar, the browser's back / forward (`WorkspacePage`'s `useBlocker`). The task editor, Quick Add and the palette itself open over an editor without closing it; the widget popup (Open larger, the popup review) covers the workspace and asks first, as Settings does (item 4). A closed tab or a reload asks nothing (the widget editors never did; nothing is kept), and an editor closed anyway — its subject gone where nothing could ask: a data replace (the draft may name a list the new data lacks, so it is dropped), an undo, a hash typed in (the router can't hold a navigation it didn't make), a cell resized too small to draw its widget whole (a divider, the window) — says so (`Edit list closed: its changes to “X” weren’t saved.`). Nothing exists yet behind Quick Add, the new-task editor and the convert preview's edited drafts, so they ask instead (Create task / Discard / Keep editing, or Discard / Keep editing with no title) — on Esc, a press on the backdrop and the new-task editor's × —, and only when the form differs from how it opened; the editor's Cancel button discards without asking. Filter and picker popovers write on every change; a date panel's pending Is not, which no clause can hold yet, is kept per filter (`filters/date-pending-not`).
