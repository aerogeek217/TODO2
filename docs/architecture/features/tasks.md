# Task writes, people and tags

**Normal use**: UI → Zustand stores → repositories → Dexie. While a sync file is syncing, Dexie hooks debounce-save to it; while paused or waiting for permission they only mark the browser dirty, which the next load resolves (written to an unchanged file, else asked about). Every task write stamps the task's `modifiedAt` (the stale fade, the Modified filter and sort read it), in the store and the database alike; **an undo puts back the stamp the task had before the step, a redo the one the step wrote** — each only where the task still holds the stamp the other left, so a task touched since keeps its newer one (`utils/task-stamps`, cr32; the same rule for field edits, completions, follow-ups, priority flags, status updates, subtasks and assignments; a delete's undo puts the row back with its stored stamp).

**A new task flies home** (flair P4, `overlays/task-fly`): when a list row on screen shows it — drawn, its centre in view and the topmost thing there (or its list `.row`, whose `content-visibility: auto` skips a just-added row's contents until a frame finds it on screen), looking through the closing Quick Add / New task editor (`FLIGHT_SEE_THROUGH_ATTR`) and the pill itself — a ghost of its title flies there from Quick Add's place, the row held closed until it lands, then opening and glowing; otherwise (no such row, a phone, reduced motion) the recent-task pill shows as before.

**People / tags**: many-to-many via `todoPeople` / `todoTags`, cached in the person / tag stores' assignment maps. Assigning or unassigning one — a row's picker, the editor, the bulk bar — is activity on the task: it stamps its `modifiedAt` in the same transaction (cr32; its undo puts the earlier stamp back); a create's people and tags are stamped once, as the create. Renaming or deleting the person or tag itself, and Find unused…'s removal, are housekeeping: they leave the tasks' `modifiedAt` alone. `Org: <name>` people and `Project: <name>` tags (from the old org / project migrations) are naming conventions only. Every People / Status / Tags filter has a "none" choice, id 0 (Unassigned, No status, No tags): `Tags is No tags` keeps untagged tasks (a triage list), `Tags is not No tags` reads "has a tag". Settings › People, statuses & tags › Find unused… (Unused people & tags, a dialog) lists the ones no task has (optionally ignoring completed tasks, noting the filters that name them) and removes the ticked ones with their assignments as one undo step; filters naming them keep the ids and stop matching, as after a single delete.
