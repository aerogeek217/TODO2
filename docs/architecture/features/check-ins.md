# Check-ins

**Check-ins** (copied, no mail): `services/checkin-email` builds each person's message from their open tasks under the saved check-in filter (a subject, `Task check-in: 3 open tasks`, and a body: a `Ref` per task; each task's box: Completed, Status — its newest status update, `(MM/DD) text` — and Notes; the footer line `Check-in for <name> · sent <date>`, which the reply import reads). The Review widget's **Check-in** button (item 13: while its filter names only people, desktop) opens the check-in dialog (`CheckinDialog`, `ui-store.openCheckinDialog(personIds)`) for those people: on the left the people — a single-select list (↑ / ↓), every person with open tasks plus the ones it was opened for, those first and the first of them selected, each with their count and `Copied ✓` once copied —, Which tasks (the saved check-in filter, written at once) and Include (task notes, other people: dialog state); on the right the selected person's subject with **Copy subject** and the message in a sandboxed `srcdoc` frame, and **Copy**, which puts the body on the clipboard as rich HTML + plain text (`person-checkin.copyCheckinMessage`). Nothing is sent and **copying records nothing** — no follow-up, no undo entry; under 760px wide the dialog is one column. Check-in and Paste reply live **only on the Review widget's field** (widget feedback 2B, decision 7 — no envelope, person-menu item, People-filter footer, person-dialog button or palette command). A person has no email and nothing about mail is stored (schema v80 removed people's `email` and the open-method setting). A reply comes back by paste (the import dialog, which reads the person from the reply): `checkin-reply` parses it, diffs it against the tasks, and applies the ticked changes as one undo group (a changed Status — read without its `(MM/DD)` — adds a status update dated today; a reply never removes one; **Record a follow-up**, on by default, is where a check-in round records its follow-up).
