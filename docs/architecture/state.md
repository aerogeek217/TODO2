# State (Zustand Stores)

Detail reference for `src/stores/`. Load when touching store APIs, filter semantics, undo, selection, or cross-store helpers.

## Stores

| useTodoStore | stores/todo-store.ts | Every task in memory and every write to one: create, update, complete, delete, duplicate, mark followed up and the bulk forms, each one undo step that also restores the task's `modifiedAt`. `setPlan` / `setPlans` write a task's plan state, `purgeCompleted` deletes completed tasks for good, and `todosVersion` counts changes to the set of tasks. ## Filter Semantics

| Abstraction | Location | Purpose |
|-------------|----------|---------|
| useFilterStore | stores/filter-store.ts | The screen (top-bar) filter: `filters` (a `FilterCriteria`), `setShowCompleted` / `setPersonIds` / `setStatusIds` / `setSearchText` / `setDateRange` (wraps Dates as fixed anchors) / `setTags` (OR semantics via `assignedTagsMap`), `setAllFilters` / `clearAll`, `applySearchTokens(tokens)` / `unwindSearchToken()` with `boxChips` (the search box's chips, oldest first: each token as typed with its field as it was before — a field set any other way drops its own, so Backspace leaves picker-set chips alone; Clear all forgets them), and a derived `isActive` (`countActiveFilters > 0`). **The top bar's typed filter** (feedback P2): `applyExpression(expression, showCompleted)` makes it the whole screen filter — `screenFilterOf`: each top-level `and` term a chip can say one chip (`splitTopLevel`, one per field, one Priority chip), the other terms `filters.expression`, ANDed with them — and records it in `typed` (`{ expression, showCompleted, filters }`); `fieldFilter(filters, typed)` gives the filter back as one expression — as typed while `typed.filters` is still the store's, else the chips (`wholeExpression`, in their order) then the expression. Not persisted, as the chips aren't; `clearAll` drops it with them. Edited by the TopBar's field and `FilterChipBar` / mobile `FilterSheet`; cleared by `App.tsx` on every pathname change. The criteria type, converters and evaluators are pure modules in `utils/` `setNegated(field, on)` switches a field between is and is not, keeping its ticks; every write is normalised (an "is not" with nothing ticked = no filter, the switch dropped with the field; the setters keep the field's switch); `clearAll` drops every switch. **`paused`** (feedback 2026-11-15, the top bar's funnel; in memory only): `setPaused(on)` pauses the filter while one is on (with none, nothing) or resumes it; every write (`commit`, `clearAll`) resumes it; `appliedScreenFilter(s)` is the filter as it applies — `NO_SCREEN_FILTER` (one frozen object) while paused, else `filters`. What widgets filter by is read through `stores/screen-filter`. |

| createAssignmentActions | stores/assignment-helpers.ts | Factory for assign/unassign/bulk/load actions shared by person + tag stores; a bulk assign / unassign is one transaction (the repository's `bulkAssign*` / `bulkUnassign*`); **an assignment is activity on its task** (cr32): each write stamps the tasks whose people / tags it changed (`modifiedAt`, in the join write's transaction — a `TaskTouch`) and tells the todo store (`task-hooks.notifyTasksStamped`), so the stale fade and the Modified filter / sort follow; its undo puts back each task's earlier stamp, its redo the one it wrote, each only where the task still holds the other (`utils/task-stamps`). Loads read through `readFresh`: it waits until no tracked write is in flight, reads, and reads again if a write started meanwhile (gives up after 5 reads with a warning).
