# State (Zustand Stores)

Detail reference for `src/stores/`. Load when touching store APIs, filter semantics, undo, selection, or cross-store helpers.

## Stores

| Abstraction | Location | Purpose |
|-------------|----------|---------|
| useTodoStore | stores/todo-store.ts | All tasks (`loadAll` / memoized `ensureAllLoaded`), CRUD and bulk operations: `add(title)` (stamps `nextFollowupAt` = today + `followupDefaultInterval`, `sortOrder` after the maximum), `addMany(items, { description, snackbar? })` (tasks with their people / tag ids in one transaction, last in order; one undo step — undo deletes them, redo puts the same rows and joins back; reloads the assignment caches), `update`, `toggleComplete` (advances recurring tasks via `advanceRecurring`), `remove`, `bulkSetCompleted`, `bulkSetStatus`, `bulkSetDeadline`, `bulkSetFollowup`, `bulkSetFocus` (on → `focus: true`, off → key removed; one undo step), `bulkSetUrgent` / `bulkSetImportant` (same shape on `urgent` / `important`), `setMarkerFlags(changes, description)` (per-task Urgent / Important writes — an Eisenhower drop; one undo step with the snackbar), `bulkClearDueDate(ids)` (removes due dates — the clearing-Urgent prompt's action; one undo step with the snackbar `Removed the due date` / `Removed N due dates`), `markFollowedUp(ids)` ("Followed up": last = now, next = today + default interval; one timestamp shared by store + DB; one undo step with snackbar), `bulkRemove`, `reorder`, `duplicate(id)` (copies title / notes / progress / dates incl. next follow-up / status / recurrence / the urgent and important flags (not focus), then the source's people and tags at repository level; undoable), `purgeCompleted(ids)` (deletes only the given ids still completed **in the DB**, backup snapshot first; called only after the launch prompt / Settings cleanup confirm; expiry keyed on `completedAt`), internal `_restore` / `_removeNoUndo` for undo / redo. Deletes also drop the tasks' manual-order ranks from `list-order-store` (`forgetTodos`). Optimistic completion state mirrors the repository's `completedAt` rule (`resolveCompletedAt`). `todosVersion: number` monotonic counter — bumped on every mutation that changes the id-set (add / duplicate / remove / bulkRemove / _restore / _removeNoUndo / purgeCompleted / load); **not** bumped on field edits (update / toggleComplete / reorder / bulkSet*). Surfaces that only care about membership changes use `${todos.length}:${todosVersion}` as an O(1) cache key — consumed by `useEntityAssignmentsForTodos` (the workspace) to gate the assignment-join-load effect |
| usePersonStore | stores/person-store.ts | People list, CRUD (`add(name, initials, color?)` — the color key is written only when a color is given; `getOrCreate(name)` — lookup-or-create by trimmed name, case-insensitive, in memory then `personRepository.getOrCreate`; new people get `generateInitials` initials and no color; used by every person picker's Create and by NLP `@name`; `update(person)` writes the whole row, so a cleared color drops the key; `remove` is undoable — `captureJoinRows` + `personRepository.restoreWithJoins`), `ensureLoaded`, `assignedPeopleMap`, todo-person assignments (`loadAssignments`, assign / unassign / bulk with undo via `createAssignmentActions`, `getAssignedPeople`) |
| useStatusStore | stores/status-store.ts | Status definitions: load / `ensureLoaded`, add, update, remove (cascade delete clears todos + the default-status setting, with undo), reorder (drag sort with persisted sortOrder). `selectTodoCountByStatusId(statusId)` — store-derived count for StatusEditor's delete confirmation, read from `useTodoStore.todos`; StatusEditor calls `useTodoStore.ensureAllLoaded()` so the cache is populated |
| useTagStore, TagLimitError | stores/tag-store.ts | Normalized tag registry (mirrors `usePersonStore` shape): `tags: Tag[]`, `assignedTagsMap: Map<number, Tag[]>`, `load` / `ensureLoaded`, `loadAssignments(todoIds)`, `add(name, color?)` (defaults to `DEFAULT_ENTITY_COLOR`; idempotent on a case-insensitive name match via `tagRepository.getOrCreate`; throws `TagLimitError` once the registry reaches `settings.maxTags`), `update`, `remove` (with undo — re-adds the cascaded `todoTags` joins via `captureJoinRows` + `tagRepository.restoreWithJoins`), `assignTag` / `unassignTag` / `bulkAssignTag` / `bulkUnassignTag`, `getAssignedTags(todoId)`. Uniqueness is enforced case-insensitively at the repository layer; `#Foo` / `#foo` resolve to the same registry row. `selectTodoCountByTagId(tagId)` + `selectTodoCountsByTag()` — counts read from `assignedTagsMap` (callers load assignments for every task first, as `TagEditor` does). A former project is a `Project: <name>` tag (schema v60) |
| useNoteStore | stores/note-store.ts | The single global "outside-tasks" note shown by every notes widget: `notes` map + `activeId`, debounced `setContent(id, content)` (`SAVE_DEBOUNCE_MS` 500) + `flush`, `lastSavedAt`; `load()` seeds the row if missing |
| useWorkspaceStore | stores/workspace-store.ts | Workspace layouts: `layouts` (saved, oldest first), `activeLayoutId`, `working` (in-memory working copy of the open layout), `saved` (its stored version), `isDirty`, `hydrated`. `init()` (idempotent: `layoutRepository.ensureDefault`, then opens the `activeLayoutId` layout, falling back to the most recently used; drops any working copy — call after startup has loaded the sync file), `load(id)` (switches unconditionally — callers resolve unsaved changes first; stamps `lastUsedAt`), `save()`, `saveAs(name)` (the new layout becomes current and saved; the source keeps its last saved state), `discard()`, `rename(id, name)` (never dirty), `delete(id)` (refuses the last; deleting the open layout opens the most recently used). **Structural edits** change only `working` and recompute `isDirty = !layoutStructureEqual(working, saved)`: `addWidget(kind, target, seed?)`, `moveTab(tabId, target)`, `closeTab`, `closeCell`, `splitCell(cellId, 'right'\|'below')`, `setColumnWeights` / `setCellWeights` (batched, by id), `patchTabConfig(tabId, kind, patch)`, `changeTabKind(tabId, kind, seed?)`. **View-state edits** — `setActiveTab(tabId)`, `setCellCollapsed(cellId, collapsed)`, `patchTabViewState(tabId, kind, patch)` — apply to `working` and to `saved` (where the target exists there) and write `saved` to Dexie at once (last write wins; `modifiedAt` untouched; never dirty). New column / cell / tab ids are random and checked against the layout. `refreshAllStores` re-runs `init()` once the store is hydrated |
| useListDefinitionStore, emptyPredicate | stores/list-definition-store.ts | Saved list definitions: load / `ensureLoaded`, add (appends with auto sortOrder; accepts membership / sort / grouping / `pinnedToDashboard` / `maxTasks` / `limitMode`), update, rename, setPinned, remove (with undo + snackbar; drops the list's ranks — `list-order-store.forgetList`; a check-in scope on the list goes back to `all`, and undo restores it unless the scope was changed since), clone (unique-name copy), reorder. Exports `emptyPredicate()` for new custom lists. Backs every list widget, the Lists manager and the Edit list dialog. `ListDefinition.runtimeFilter?: RuntimeFilterSpec` declares a per-render picker field (`person` / `status` / `tag`); the *value* is *not* stored on the def — workspace list tabs keep their picks in `list-widget-store` (never saved) and feed them to `buildDashboardLists` via `ctx.runtimeFilterValues: ReadonlyMap<defId, number[]>` (through `useBuiltList`). Picks are OR-combined arrays; an empty array means no narrowing. Unsaved edits to a definition live in `list-draft-store`, not here |
| useListDraftStore, useEffectiveListDefinition, useIsListDirty, useUnsavedListIds, getUnsavedListIds, draftListIds | stores/list-draft-store.ts | Unsaved edits to list definitions, keyed by list id and shared by every widget showing the list (in memory only). `edit(id, fn)` applies `fn` to the draft (else the saved def) and drops the draft when the result `defsEqual`s the saved def; `save(id)` writes it through `useListDefinitionStore.update` (blank name → the saved name; restored as a draft if the write fails); `discard(id)`. Drafts of deleted lists don't count as unsaved. Cleared by `refreshAllStores` |
| useListOrderStore, useListRanks | stores/list-order-store.ts | Manual list order: `ranks` (list id → todo id → rank), loaded once (`ensureLoaded`, from `useBuiltList`; reloaded by `refreshAllStores`). `setRanks` (a move) and `replaceList` (switch to manual) update memory then save at once — order changes are never part of a list's unsaved draft. `forgetTodos` / `forgetList` drop deleted rows from memory (todo-store / list-definition-store call them after the repository cascades); `restoreRows` is their undo |
| useListWidgetStore, ListPopover, PopoverPoint | stores/list-widget-store.ts | Never-saved list widget state: prompt picks (`picks[tabId]`, `setPicks`; empty = nothing picked) and collapsed group keys per layout tab (`toggleGroup`), and the one open list popover (`options` / `add-filter` / `picker`; `openPopover` / `closePopover`) that `ListOptionsHost` renders. Cleared by `refreshAllStores` |
| useUIStore, BulkConfirmation | stores/ui-store.ts | Transient UI state. Selection: `selectedTodoId`, multi-selection (`selectedTodoIds` Set, `selectionAnchorId`, `selectionFocusId`, `focusedTodoId`; `selectTodo`, `selectOneTodo`, `toggleSelectTodo`, `rangeSelectTodo`, `selectAll`); a list widget's selection is **scoped** (`selectionScope` = the widget's tab id, `selectionAnchorKey` / `selectionCursorKey` = row occurrences, set via `setScopedSelection` from `utils/scoped-selection.nextScopedSelection`) so it lives in one widget at a time and a task shown twice is walked once per row — the unscoped setters clear the scope, `clearSelection` clears it too. `hoveredTodoId` + `setHoveredTodoId` (cross-surface hover sync — TaskRow + MobileTaskRow read via selector, write on mouseenter/leave). Task editor: `editPopupMode` + `openEditPopup(id)` / `openCreatePopup()` / `closeEditPopup()` (also clears `quickAddDraft`). `bulkConfirmation` + `showBulkConfirmation(action, ids, options?)` / `clearBulkConfirmation` (delete / complete / uncomplete / `custom` with title, message, labels, `skipIds`, `onConfirm`; rendered by `App.tsx`'s `AppBulkConfirmDialog`). `taskDialog: TaskDialogPayload | null` (`services/task-dialog`) + `showTaskDialog(payload)` (also clears the selection, so a row's actions in the dialog act on that row only) / `hideTaskDialog` — rendered by `overlays/TaskDialog`. `checkinDialog: { personIds } | null` + `openCheckinDialog(personIds?)` (de-duplicated; none = nobody ticked) / `closeCheckinDialog` — rendered by `overlays/CheckinDialog`. `checkinImportOpen` + `openCheckinImport` (also closes the check-in dialog) / `closeCheckinImport` — `overlays/CheckinImportDialog`. Mobile filter sheet: `isFilterSheetOpen`, `filterSheetFocusSearch`, `toggleFilterSheet`, `setFilterSheetOpen`, `openFilterSheetSearch`. **Lists manager:** `listsEditorOpen` + `listsEditorInitialId` + `openListsEditor(initialId?)` / `closeListsEditor()` (clears both) — `WorkspacePage` renders `DashboardListsEditor` with `initialSelectedId` while it is open (also over the Settings modal). **Direct list editor dialog:** `listEditorDialogId` + `openListEditorDialog(id)` / `closeListEditorDialog()` — drives `<StandaloneListEditor>` (list tab menu, List options, mobile list tab sheet) without the Lists modal underneath; the two slices are deliberately disjoint. **Quick Add:** `quickAddOpen`, `quickAddDraft: QuickAddDraftSeed { rawTitle, defaults?, source? } \| null` (`defaults` = a list's predicate seed from "+ Add task" or an Eisenhower quadrant's flags; `source` = where the task is added, shown as `Adding to <source>`; also the Details → create-popup handoff), `openQuickAdd(seed?)`, `closeQuickAdd()`, `setQuickAddDraft`. `recentlyCreated: { todoId, key }` + `showRecentlyCreated` / `clearRecentlyCreated` (the transient `RecentTaskPill`). **Settings modal (desktop):** `settingsOpen`, `settingsSection: SettingsSectionId` (the section shown — kept while the app stays open, default `appearance`), `openSettings(section?)` (the gear, `G S`, Open Settings, the storage pill, the `#/settings` deep link), `closeSettings`, `setSettingsSection` |
| useUndoStore | stores/undo-store.ts | Undo/redo stacks (max 50), push/undo/redo/clear, isPerformingUndoRedo guard, beginGroup/endGroup (compound ops: while a group is open, pushes neither trim the stack nor show a snackbar — `endGroup` trims and decides the snackbar), snackbar state with auto-dismiss |
| useSettingsStore, ThemeMode, resolveTheme | stores/settings-store.ts | Settings loaded from the `settings` table: `themeMode` (light / dark / system), per-theme color overrides `colors: ThemedColors { dark, light }` over the nine `ThemeColors` keys (accent / canvasBg / surface / border / header / danger / warning / star / deadline), `defaultStatusId`, `quickStatusId` (one-click status toggle; none unless picked), `seededAssignedStatusId`, `completedRetentionDays` (null = keep forever), `weekStartsOn` (0=Sunday, 1=Monday — default 1; consumed directly by every helper that needs week math), `maxTags` (tag registry ceiling; no UI — a `maxTags` row overrides the default), `followupDefaultInterval` (`FollowupInterval`, stored compact `1m`/`2w`/`10d`, default 1 month), `urgentDueWithinDays` ("Due date makes a task urgent": days ahead, `0` = today, `null` = off; stored `off` or the day count, absent = 3 — `utils/urgency`), `hotRule` (`HotRule`, OR of AND-lines over Urgent / Important / Focus; stored as normalized JSON, absent or invalid = `(Urgent AND Important) OR Focus` — `utils/hot`), `checkinOpenMethod` (`mailto` default / `eml`) and `checkinTaskScope` (`CheckinTaskScope`, default `{ kind: 'all' }`; stored compact — `utils/checkin-settings`; a `list` scope can name a deleted list, so readers go through `resolveCheckinTaskScope`). The filter evaluators read both through `currentMarkerSettings()` unless the caller passes its own subscribed copy. Invalid stored values fall back to defaults on `load()`. Color rows live under `color.dark.<key>` / `color.light.<key>`; `applyThemeOverrides(customizedKeys, themedColors, resolvedTheme)` reads only the resolved-theme bag and writes one inline `style.setProperty(...)` per customized key (uncustomized keys fall through to the `tokens.css` `[data-theme]` block). `setThemeMode` + the `matchMedia('(prefers-color-scheme: dark)')` 'system' handler re-run `applyThemeOverrides` with the freshly-resolved theme on every flip. Setters: `setColor(theme, key, value)` writes the per-theme row + applies overrides only when `theme === resolvedTheme`; `resetColors(theme?)` resets one bag (or both when omitted); `setThemeMode`, `setDefaultStatusId`, `setQuickStatusId`, `setCompletedRetentionDays`, `setWeekStartsOn`, `setFollowupDefaultInterval`, `setUrgentDueWithinDays` (Off · Today · 1 · 2 · 3 days · 1 · 2 weeks from Settings › Task defaults; any 0–365 accepted), `setHotRule` (saves the rule normalized; a rule with no marker is ignored), `setCheckinOpenMethod` / `setCheckinTaskScope` (state first, then the write — they back controlled radios; reverted if the write fails). `ThemedColors` / `ThemeName` / `ThemeColors` / `DEFAULT_THEMED_COLORS` are re-exported from `models/theme-colors` |
| useFileStorageStore | stores/file-storage-store.ts | File storage connection state (incl. `paused`, `needsPermission`, `lastSavedAt`, and `dismissedError` + `dismissError()` — the warning strip's ×, which the storage pill follows too) and actions (`initialize`, `openFile`, `createFile`, `disconnect`, `reconnect`, `retry`, `overwriteFileWithBrowser`). Bridges the service's promise-based prompts to dialogs: `pendingLegacyImport` (MigrationDialog; `confirmLegacyImport` / `cancelLegacyImport`), `pendingConflict` → `resolveConflict(choice)` (SyncConflictDialog), `pendingFileUpgrade` → `resolveFileUpgrade(ok)` (FileUpgradeDialog) — all rendered by `App.tsx` `FileMigrationOverlay`, outside AppShell, so they show while startup awaits them |
| useFileOpsStore | stores/file-ops-store.ts | Data-ops store consumed by the Settings sections (Backups, Data integrity, Import / Export): `backups` list + `loadBackups` / `createBackup` / `deleteBackup` / `peekBackupData` / `restoreBackup` (delegates to `backupRepository`); `auditReport` + `runAudit` / `setAuditReport` / `cleanupCurrentAudit` (delegates to `data/audit`); `restoreFromImport` (delegates to `data/restore`); `snapshotWarning` + `dismissSnapshotWarning` (backup self-check warning shown by `FileSyncBanner`). Keeps the view free of direct `data/*` imports |
| useTrendEventsStore, trendEventsKey, TrendEventsEntry | stores/trend-events-store.ts | Cache of the `todoEvents` the dashboard trend reads, per (range, week start, day) key: `load(range, today, weekStartsOn)` does one indexed read (`todoEventRepository.since(window start, TREND_EVENT_TYPES)`) unless the entry is fresh or loading, and drops other days' entries; `invalidate()` marks every entry stale (events kept on show) and bumps `generation`, so a read it overtakes lands stale; a failed read logs and keeps what was shown |
| refreshAllStores | stores/refresh-all.ts | Reloads every store after a destructive replace (file import, backup restore, audit cleanup, legacy migration): clears undo, the screen filter, list drafts and list widget state, invalidates the trend events cache, reloads settings, then todos / people / statuses / tags / note / list definitions / list order (via `load()`, not `ensureLoaded()`, which would keep the pre-import data) and re-inits the workspace when hydrated, then refetches person / tag assignments for every task (`{ refetch: true }`) |

## Filter Semantics

| Abstraction | Location | Purpose |
|-------------|----------|---------|
| useFilterStore, FilterCriteria | stores/filter-store.ts | The screen (top-bar) filter: criteria (personIds, statusIds, tags as null\|Set of number ids; showCompleted, searchText, dateField (`deadline` = due date, the default / `followup` = next follow-up / `created` / `modified`), dateRangeStart/End (`DateAnchor`s), dateRangeIncludeNoDate (keeps tasks with no due date; due-date field only), hasDeadline, hasFollowup, markers — the Markers filter (`MarkersFilter \| null`: `'hot'` = hot by `settings.hotRule`, or every ticked marker required, Urgent = effective urgent against `settings.urgentDueWithinDays`; `setMarkers` normalizes `{}` to null; `utils/markers.matchesMarkers`)), one setter per field plus `setAllFilters` / `clearAll`, and a derived `isActive`. `setTags(Set<number>\|null)` sets the tag-id clause (OR semantics via `assignedTagsMap`). Edited by the TopBar `FilterChipBar` / mobile `FilterSheet`; cleared by `App.tsx` on every pathname change |
| countActiveFilters | stores/filter-store.ts | Number of active screen filters, one per control (people, status, tags, dates — range or due / follow-up presence count once —, markers, show completed, search); `isActive` is `count > 0`. Drives the mobile Filters badge |
| matchesFilter / matchesFilterWithLookups / applyFilter / createPredicateEvaluator | stores/filter-store.ts | Top-level evaluators (not store methods). `matchesFilter(filters, todo, personIds?, today?, searchCtx?, tagIds?)` is the core: person filter is plain set membership over the todo's assigned people (`0` = unassigned sentinel); statuses never hide tasks by themselves; optional `today` anchors relative date-range tokens; a non-null tag clause excludes tasks with no tag assignments. `matchesFilterWithLookups(filters, todo, lookups, today?)` resolves people / tag ids and the search context (`utils/filter.textMatchContextFor`) from `TodoNameLookups` — the one path behind both `applyFilter(filters, todos, peopleMap?, statuses?, today?, tagsMap?)` (the calendar widget) and `createPredicateEvaluator(lookups, today)` (list widgets' `evalPredicate` for stored `TodoPredicate`s; converts each predicate to criteria once), so search hits person / status / tag names on every surface |
| composeScreenFilter / matchesComposedFilter / createScreenComposedEvaluator | stores/filter-store.ts | The screen (top-bar) filter composed with a list's own filter, as two stages a task must both pass: narrowing clauses AND strictly (even on the same field — screen `@Alice` + list `@Bob` = tasks assigned to both), `showCompleted` ORs into both stages. `createScreenComposedEvaluator(screen, lookups, today)` is the `evalPredicate` list widgets pass to `buildDashboardLists` |
| criteriaToPredicate / predicateToCriteria | stores/filter-store.ts | Converters between runtime `FilterCriteria` (Sets) and serializable `TodoPredicate` (arrays); `predicateToCriteria` reads date anchors through `utils/date-anchor.readDateAnchor`. Crossed at storage / evaluation boundaries (list predicate evaluation, the mobile filter sheet, filter defaults from a stored predicate) |

## Store Helpers

| Abstraction | Location | Purpose |
|-------------|----------|---------|
| createAssignmentActions | stores/assignment-helpers.ts | Factory for assign/unassign/bulk/load actions shared by person + tag stores. `loadAssignments(todoIds, {refetch?})` fetches only ids missing from the map (the map ends up holding exactly `todoIds`; entries written optimistically during the fetch win); `refetch: true` re-reads every id — `refreshAllStores` uses it after a restore / import, where a todo can keep its id while its people / tags change |
| makeEnsureLoaded | stores/store-helpers.ts | Memoize a `load()` so callers can fire `ensureLoaded()` on every mount without re-hitting IndexedDB. Concurrent callers share the same in-flight promise; once the first load resolves, subsequent calls are a no-op until `resetLoaded()` is invoked (e.g. after an import / DB reset). Each entity store keeps one instance and exposes the action as `ensureLoaded` / `ensureAllLoaded`: `useTodoStore.ensureAllLoaded`, `usePersonStore.ensureLoaded`, `useStatusStore.ensureLoaded`, `useTagStore.ensureLoaded`, `useListDefinitionStore.ensureLoaded` |
| trackWrite, readFresh | stores/store-helpers.ts | Keep a `load()` from putting back rows an edit changed while its read was in flight. Every store write (state change + database write) runs through `trackWrite` — `mutate` / `optimistic` do it for their callers; the other writes of the todo / person / tag / status / list / list-order / settings stores wrap themselves. Loads read through `readFresh`: it waits until no tracked write is in flight, reads, and reads again if a write started meanwhile (gives up after 5 reads with a warning). One app-wide tracker, so e.g. a todo load also waits for a status delete that clears `statusId`s. Rule: a tracked write never awaits a `readFresh` load (deadlock); `loadAssignments` doesn't use it (it merges with the latest map instead), so writes may call it. Not covered: the workspace store (`init` / `load(id)` open a layout — no edit can be pending) and the note store (its load runs at startup / after an import; a typed note saves on a debounce). `resetWriteTracking` is the shared vitest setup's file-boundary reset |
| loadWithState | stores/store-helpers.ts | Loading/error state boilerplate around a `readFresh` read |
| mutate | stores/store-helpers.ts | Tracked error-handling wrapper for store mutation actions (clears error, catches failures, logs, sets error state) |
| optimistic | stores/store-helpers.ts | Tracked optimistic mutation: applies state synchronously, persists async, rolls back on failure; undo registered only after successful persist |
| updateEntityInMap | stores/store-helpers.ts | Refresh entity references in assignment maps when entity is edited |
| captureAssignments, captureAssignmentsBulk | stores/store-helpers.ts | Capture person assignment IDs for todo undo (delete / duplicate) |
| bulkUpdateField | stores/store-helpers.ts | Generic bulk field update with undo for todo store |
