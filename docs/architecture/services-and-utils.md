# Services, Hooks & Utils

Detail reference for `src/services/` (non-UI logic), `src/hooks/` (custom React hooks), and `src/utils/` (pure utilities). Load when touching NLP, recurrence, file storage, list interpretation, drag-and-drop logic, keyboard shortcuts, or date helpers.

## Services

|-------------|----------|---------|
| Section, ListSectionsSpec, ListSectionsContext, buildListSections, listSortComparator, isUngroupedSectionKey | services/list-sections.ts | The one section builder for list widgets (`buildList` → `useBuiltList` → `ListWidget`), so the same definition yields the same sections in every widget. `buildListSections(members, {groupBy, sortBy, sortDirection?, restrictToPersonIds?, restrictToTagIds?}, ctx)` sorts with `listSortComparator(sortBy, { direction: sortDirection, … })` first (so every section comes out sorted; grouping keeps input order), then partitions through `utils/task-grouping.partitionByGroup`. Sections: due / follow-up → Overdue (`--color-overdue`) / Today (`--color-accent`) / This Week (`--color-text-secondary`) / Later (`--color-text-muted`), then "No Due Date" / "No Follow-up" (key `none`; every trailing "No …" / Unassigned section is `--color-text-muted`); people → person name, accent `person.color` (undefined when unset), alphabetical, then "Unassigned"; status → registry `sortOrder`, status color, then "No Status"; tag → `#name`, tag color, alphabetical, then "No Tag"; priority → Hot (`HOT_COLOR`, the flame), Focus, Urgent, Important (each `MARKER_COLOR`), then "No priority" (key `no-priority`) — Hot by `ctx.hotRule` (absent = the default rule; open tasks only), Urgent effective by `ctx.urgentRange` (absent = flags only); `none` → one `all` section (none when empty). A stored grouping this build doesn't know reads as `none`. Restrict mode (the effective filter's person / tag picks): only those sections, in pick order; the trailing sentinel is dropped unless the person picks include `0` (Unassigned). A task with several people / tags / priority groups appears in each of them; empty groups aren't shown. `listSortComparator(sortBy, { manualRanks?, today?, urgentRange?, direction? })` (`ListSortContext`; `direction: 'desc'` reverses the primary key only — latest / newest / Z → A / lowest priority first — while ties keep their tie-break and undated tasks stay last; Manual and `people` / `status` ignore it; `ctx.urgentRange` / `ListBuildContext.urgentRange` = Settings' urgent range): `priority` → `utils/markers.priorityRank` (Focus, then Urgent + Important, Urgent, Important, none; Urgent = effective, due soon included; flags only without a range), ties by due date (undated last), then manual order (the ranks when given, else `sortOrder`); `manual` → the list's ranks when `ctx.manualRanks` is given (`utils/list-order.manualOrderComparator`: ranked by rank, then unranked oldest first — list widgets via `ListBuildContext.ranks`), else `sortOrder` then id; `name` → `title.localeCompare` then `sortOrder`; `deadline` / `followup` → `compareTodosByDate` (undated last); `created` → `createdAt` oldest first, then `sortOrder`; `people` / `status` have no order of their own and fall back to `sortOrder`. `isUngroupedSectionKey(groupBy, key)` recognises the trailing "No …" / Unassigned section (cross-group drops map it to `UNGROUPED_GROUP_KEY`) |

| buildList, matchesMembership, applyRuntimeFilter, ListContents, ListBuildContext, PredicateEvaluator | services/build-list.ts | Runs one `ListDefinition` over the tasks (called by `useBuiltList` and the task dialog's list source). Merges the prompt pick (`ctx.runtimeFilterValue`) into the predicate with `applyRuntimeFilter`, decides membership through the required `ctx.evalPredicate` (the app passes `utils/filter-match.createPredicateEvaluator` or `createScreenComposedEvaluator`) via `matchesMembership`, sorts (`ctx.ranks` = the list's manual order; omitted → `sortOrder`; `ctx.urgentRange` for the Priority sort and groups, `ctx.hotRule` for the Priority groups' Hot; the definition's `sortDirection`), then builds sections with `services/list-sections.buildListSections` using the effective predicate's `personIds` / `tags` as the restrict picks. A missing pick → `{ todos: [], sections: [], runtimeFilterUnset: true }` so the widget shows its "pick a value" placeholder. `matchesMembership(membership, todo, evalPredicate)` is the membership test alone, also used by the dashboard's list tiles (`stats/list-tiles`) `applyRuntimeFilter` replaces the prompted field as "is" (the list's "is not" switch on it goes); an "is not" people / tag filter doesn't restrict the people / tag groups (its members have none of the ticked values). |

| fileStorageService | services/file-storage.ts | File System Access API sync (file ↔ IndexedDB). **The user decides before anything changes:** **Launch** (`initialize()`, shared by concurrent callers): a granted handle loads at once; one that needs permission marks `needsPermission` and asks the launch question (`onLaunchPermission`) — `initialize` resolves only once it is answered (`reconnect({ onGranted })` from the question's Grant: `onGranted` fires as soon as the browser says yes, before the load; Continue resolves with permission still needed). A load (startup / Grant Access / attach / `retry()`) reads + `prepareImport`s the file without touching either side, then: any failure (too large, read error, invalid JSON/rows, too new, upgrade failed) → **paused** (`status.paused = {reason, message}`, no restore, never writes; a file `getFile()` still can't find after looking twice more — 0.4 s, then 0.8 s later: a cloud folder may be renaming a new copy into place — forgets the handle). Reads go through private `readFileText` (50 MB cap before reading; a `File` snapshot that a save replaced mid-read — `NotFoundError` / `NotReadableError` from `text()` — is read again, up to 3 times, then `read-error`) and wait for `whenIdle()` first; below floor → `onConfirmMigration` (cancel → paused); unsynced browser changes (`dirtySince`) over the very file this browser last synced with (`fileSavedAt` = the file's content id — a tab closed within the save debounce, edits while permission was needed or sync paused) → the browser is only ahead: its data is written to the file without a prompt (the file text backed up first, as `'browser'`; an older file asks `onConfirmFileUpgrade` first, cancel → paused); unsynced browser changes over a file changed since, or no sync record while the browser has tasks → `onConflict` → `'file'` (browser backup via `takeSafetySnapshot` → restore; a failed backup asks, Cancel pauses with `backup-failed`) / `'browser'` (file text → `backupScheduler.snapshotFileBeforeOverwrite` → overwrite) / `'cancel'` (paused) — skipped when `browserMatchesFile` says both sides already hold identical data (an older file is compared after its upgrade, so a browser that came from a build without a sync record and was upgraded at open matches its in-sync file and gets the upgrade prompt instead); clean browser synced with an earlier version of the file → loads it (multi-machine); older-but-supported file → `onConfirmFileUpgrade` first (cancel → paused), then restore + restamp. **Events:** `onStatusChange` adds a subscriber and returns its unsubscribe — every subscriber gets every change (one that throws is logged). A load that replaces the browser data is a data replace (`replace-data.replaceData('sync-file', …)`): the stores reload and `onDataReplaced` listeners hear it there. The questions (`onConfirmMigration` / `onConflict` / `onConfirmFileUpgrade` / `onLaunchPermission`) have one answerer: a later handler replaces an earlier one, and each returns a removal that is a no-op once replaced. Missing handlers resolve to the safe answer (stay paused). Change-tracking Dexie hooks stay installed whenever a file is attached (also while paused / needing permission) and mark the browser dirty; writes only happen while `syncEnabled`; switching sync on (`startSync`, after every load / forced write) saves any change recorded while it was off (e.g. a store seeding a row as it reloaded), so nothing is left unsynced for the next start to ask about. `overwriteFileWithBrowser()` (the storage pill's "Keep browser data…") backs up the file text then overwrites and resumes (a file over 50 MB isn't read: `backup-failed`, untouched). **Writes never overlap** (`saveInFlight`): a debounced save asked for during one is rescheduled after it; a forced write (create / overwrite / upgrade / empty-file seed) waits for it and then writes — never dropped; a save writes only the handle it started on and sets the sync record only if that file is still attached. `whenIdle()` resolves once no write is running or scheduled (the load path, and the e2e `readSyncFile` fixture, wait on it). Failures are logged (`console.warn`) and surfaced in `status.error` / the paused message — except a `NotAllowedError` from `getFile()` / `text()` / `createWritable()` / a write (the browser took its permission back mid-session, or refuses a read at load): that sets `needsPermission` (sync off, the handle kept, the storage pill's Permission needed → Grant access → `reconnect`, whose load writes the edits made meanwhile to an unchanged file), never `Failed to save to file` or a pause. **Every write of existing file content** (confirmed upgrade, below-floor confirm, either conflict choice that rewrites the file, a browser only ahead of an unchanged file, keep-browser overwrite) first backs up the raw file text (private `backupFileText` → `backupScheduler.snapshotFileBeforeOverwrite`); a failed backup or unreadable file pauses with `backup-failed` and nothing is written — any new write path must do the same. A confirmed upgrade whose rewrite of the file fails pauses with `write-failed` (the browser holds the upgraded data, the file the old one; Retry asks again). A current-version file that `prepareImport` trimmed (it returned warnings — parts dropped) also has its raw text backed up before the load, since the first sync write rewrites it without them. Loads are latest-wins: each one bumps a generation, and an older load still waiting on a question (the store answers it as cancelled) stops at its next await without pausing or writing; `disconnect` / `reset` make a running load stale too. Every write is checked as an export is: over the 50 MB load cap (each write), or failing the import self-check (`selfCheckExportJson` — forced writes, else at most once a minute) → still written, and the status error says `Saved, but the sync file would not load back: …` until a clean write. `openFile`/`createFile`/`disconnect` reset the sync record; `openFile` / `createFile` store the picked handle (`saveFileHandle`) before switching to it — when the browser can't, nothing switches (the file attached before stays, syncing) and the status error says so. `createFile` suggests `todo2-data-YYYY-MM-DD.json` (`newSyncFileName`, local day): the browser empties an existing file picked in the save dialog before `showSaveFilePicker` resolves, so its text can't be backed up — the dated default keeps the suggestion off an older sync file, and Settings › File storage says so. `isConnected` = actively syncing. Every load that replaces browser data goes through `takeSafetySnapshot` (a failed browser backup asks "Continue without a backup?"; Cancel pauses with `backup-failed`, nothing changed) — except when the browser already holds exactly this file's data (identical — after the file's upgrade, if any — or clean and synced with this file version), where a failed backup is only logged since the load loses nothing. The load decision runs inside `replace-data.withDataReplaceHold` (the note store's hold — taken before the decision compares the two sides, so typed note text is saved first: the comparison sees it as a browser change and every backup holds it; released once the decision is carried out, or on Cancel / a pause); the backup, the restore and the reload are `replaceData`'s (a lossless load's backup is `best-effort`). `clearFileHandle` failures are logged with `console.warn`. `reset()` (tests sharing one module instance) puts the service back as at module load — no file, no sync, no timers or Dexie hooks, idle — and keeps its subscribers |
