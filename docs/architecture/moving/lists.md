### useListDefinitionStore — stores/list-definition-store.ts

List definitions (every layout's — never the removed Eisenhower's hidden list, which the repository leaves out; choosers filter through `listedLists(defs, layoutId)`): `editList(id, fn, description)` — a list edit written for good as one undo step with the snackbar (Edit list's Save, a drag switching a sorted list to manual): `fn` over the stored definition, of which only the editors' parts count (the id, sort order and owner stay the stored ones; a blank name keeps the stored one); Undo / Redo write back only the keys the step changed (`utils/config-patch`), over the list as it is then, `UndoGone` once it is gone; resolves false for no change, an unknown list, a failed write (`Couldn't save list “X”.`) or a data replace's hold (`replace-hold`); `forgetLists(ids)` — lists deleted with their layout out of the state (and their ranks); load / `ensureLoaded` (a failed load is reported as `lists`), add (goes last — `listDefinitionRepository.insertLast` picks the sort order in its transaction; accepts membership / sort (+ `sortDirection`) / grouping / `runtimeFilter` / `showFilterLine` and a required `owner` — the layout whose tab shows it; a sort or grouping not given is Settings' new-list default — `newListSort` + `newListSortDirection` / `newListGroup` — so a blank list (a new List widget) starts with them), update (a failure rolls back only that list; nothing under a data replace's hold). Lists are deleted only with their layout (`workspace-store`). New custom lists start from `emptyPredicate()` (`models/filter-predicate`). Backs every list widget and the Edit list dialog. `ListDefinition.runtimeFilter?: RuntimeFilterSpec` declares a per-render picker field (`person` / `status` / `tag`); the *value* is *not* stored on the def — workspace list tabs keep their picks in `list-widget-store` (never saved) and feed them to `buildList` via `ctx.runtimeFilterValue` (through `useBuiltList`). Picks are OR-combined arrays; an empty array means no narrowing. Edit list's draft lives in `list-draft-store`, not here

### useListWidgetStore, ListFilterField, PopoverPoint — stores/list-widget-store.ts

Never-saved list widget state: prompt picks (`picks[tabId]`, `setPicks`; empty = nothing picked — a list tab's runtime prompt), each Review widget's filter (`reviewFilters[tabId]`, `setReviewFilter(tabId, filter | null)`; `ReviewFilter` `{ expression, showCompleted }`, the last text its field read — widget feedback 2A, temporary the same way) and collapsed group keys per layout tab (`toggleGroup`; `setCollapsed(tabId, keys)` sets them at once — the tab menu's Collapse all / Expand all groups); and each list tab's tasks as shown while its widget is on screen (`shown[tabId]`: `ShownList` — the list's name, its words, whether grouped, its sections in display order, collapsed groups too; written by `ListWidgetBody` / `ListFace` through `use-shown-list`, removed when the widget goes; `setShown`) — what a review of the tab counts (`services/review.listReviewCount`; its filter, `listReviewFilter`, reads the tab's `listId`); the zoom level each list tab on screen shows (`zoom[tabId]`, `setShownZoom`; written by `ListWidgetBody` — its own pick, else the Default list zoom with Auto resolved by its width —, removed when it goes): what the ⋯ Zoom stepper, Ctrl + wheel and the palette step from (`services/list-zoom.listTabZoom`); also the filter-picker types (`ListFilterField`, `PopoverPoint`). A write drops the picks / collapsed groups of tabs that are in no layout any more (not in the working copy or a saved layout); a Review filter's write drops those tabs' reviews too (`review-session.keepReviewSessions`). The popup review's filter is kept under `REVIEW_POPUP_TAB_ID`, which the gone-tabs pruning never drops. **A data replace** calls `resetForReplacedData()`: `CLEARED_ON_REPLACE` says for every field whether it goes (picks, Review filters, collapsed groups: they name ids the new data may reuse) or stays (`shown`, `zoom`: the widgets on screen write them again) — a new field has to say which. Every record by tab id has no prototype and the store reads its own keys only, so a tab id such as `constructor` reads as absent. `reviewFilterKey(filter)` says which review a filter is (its text with names by id; null for none): the same filter sent or printed again is the same review.
