## From state.md

### useNoteStore — stores/note-store.ts

The single global "outside-tasks" note shown by every notes widget: `notes` map + `activeId`, debounced `setContent(id, content)` (`SAVE_DEBOUNCE_MS` 500; the page hidden or closed saves the pending text at once — `utils/page-hide`) + `flush`, `lastSavedAt`. `load()` seeds the row if missing (`noteRepository.getOrSeedGlobal`, one transaction); concurrent loads share one (`loadInFlight`); text still unsaved stays what the store shows. The latest edit is `pending` (sequenced) until a save of it or newer text succeeds: saves run one at a time, each writes the latest text (`saveContent` — content + `modifiedAt` only) and never puts older text back into the store. A failed save keeps the text, sets `saveFailed`, shows `Couldn't save your notes. They'll be saved with your next change.` once (undo snackbar notice) and is retried by the next change or `flush`; `flush` never rejects. `discardPending()` drops unsaved text and its scheduled save (`refreshAllStores` calls it). `holdForDataReplace()` — called before every data replace takes its backup (`services/replace-data` — every replace goes through it; a sync file load holds from before its load decision, `withDataReplaceHold`): holds nest (only the outermost saves and drops — text typed during an outer hold stays pending); saves the text typed so far (`flush`, which also waits for a save already started — so the pre-op backup holds it; if that save fails the text is dropped and the replace goes ahead), then holds every later save (`replaceHolds > 0`; text typed meanwhile is dropped by the reload) until the returned release — called after the stores reload, or when the replace was cancelled or failed (text typed meanwhile is then saved). So no save can land after a replace, and text typed just before one is recoverable from Settings › Backups. It waits only on note saves (untracked, never on a load), so it can't deadlock with the replace `resetNoteSaves()` (tests sharing one module instance) clears the save timer and the save chain.
