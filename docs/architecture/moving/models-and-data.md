### DataSet, DataRow, SchemaUpgrade, SCHEMA_UPGRADES, upgradeDataSet, applySchemaUpgradeInTx — data/schema-upgrades.ts

**Permanent import upgrade pipeline.** `SCHEMA_UPGRADES: Map<targetVersion, (DataSet) => DataSet>` — pure, immutable, whole-dataset transforms (table name → plain rows) that tolerate missing tables (partial datasets like task archives) and return the same array ref for untouched tables. **Thirteen entries: v69** (`upgrades/v69-or-groups.ts` — a version marker returning its input: v69 data may hold stored or groups, `orGroups`, which a v68 build would drop silently; v75 converts them), **v70** (`upgrades/v70-date-types.ts` — the same: v70 data may hold `dates.lastFollowup` / `dates.completed` clauses and `lastFollowup` / `completed` sorts, which a v69 build would drop) **and v71** (`upgrades/v71-date-not.ts` — the same: v71 data may hold an "is not" date range, `DateRangeMatch.not`, which a v70 build would read as "is", keeping the opposite tasks) **and v72** (`upgrades/v72-status-updates.ts` — each task whose `progress` is non-blank (and whose id is a whole number from 1) gets one `statusUpdates` row: the trimmed text capped at 500, dated the local day of its `modifiedAt` (else `createdAt`; neither → no entry), `createdAt` = that moment; every `progress` key goes. Dates keep their form (ISO strings in a file, `Date`s in Dexie); idempotent on todoId + text; the `statusUpdates` key is added only with rows (an archive is partial); its rows carry no ids, so the sync compare ignores that table's ids — `file-sync-compare`) **and v73** (`upgrades/v73-subtasks.ts` — a version marker returning its input: v73 adds the `subtasks` table, which a v72 build knows nothing of and would drop every checklist) and **v74** (`upgrades/v74-priority-filter.ts` — every stored Priority filter as conditions, exactly what it matched: a chip per Yes, the No markers one `is not` chip, Hot as the stored `hotRule` in conjunctive form, an AND in an or group distributed into several groups — the most a v73 filter can need, 30, is why `predicate-shape` still reads up to `OR_GROUPS_READ_MAX` (30) or groups; the rule read with its picks kept once each — at most 8, so a crafted long rule can't blow up an import; it then deletes the `hotRule` settings row and removes `hot` from stored dashboard tabs' tiles and sections, and makes every subtask title what the store writes (one line, at most 500 characters; a row with none goes) — v73 builds stored a note line's subtasks as they were, which import refuses, so this repairs both the browser's database and every file a v73 build wrote (cr31 data H1); a row that isn't an object passes through, for validation to name) and **v75** (`upgrades/v75-filter-expressions.ts` — a stored filter with or groups as the expression that filters the same, over list definitions, the `lenses` / `eisenhowerPanes` / `checkinTaskFilter` settings rows and kept list drafts: each clause outside the groups one `and` term in the chips' order (an id filter `@a or @b`, its "is not" a `not`; each Priority condition likewise; each date clause a `date` atom — an "is not" range a `not`, "or none" an `or … none`; text a `text` atom), each or group an `or` of its clauses' terms, an expression already there the last term; the clauses emptied, `orGroups` and `negate` gone. It holds its own copy of the conversion, so the step keeps meaning this whatever later builds do; a clause it can't read leaves the predicate as it was, for validation to judge; a filter without or groups stays as it is — idempotent) and **v76** (`upgrades/v76-layout-rows.ts` — every column is rows, over `layouts` and kept layout drafts: each cell of a column a one-cell row `{ id: <cell>-r, weight: the cell's, collapsed: the cell's, cells: [the cell, weight 1] }`, each band `{ id, height, collapsed, cells: [{ id: <band>-c, weight 1, tabs, activeTabId }] }`; a fresh id is cut to stay within 100 characters and takes `2`, `3`, … when the layout already holds it at any level, so the same layout always upgrades to the same ids (a draft's base to what its stored layout does); a part it can't read passes through for the repair; a column with `rows` and a band with `cells` stay — idempotent) and **v77** (`upgrades/v77-dashboard-widgets.ts` — the Dashboard retires, over `layouts` and kept layout drafts: each `dashboard` tab's config read as the Dashboard read it (known ids once each; a missing `tiles` / `listTiles` / `sections` its default) becomes its parts, one tab per cell — each tile a `number` tab `{ metric }`, each list tile a `lens` tab `{ listDefinitionId }` (so `layoutListRefs` still names the list), each section its glance kind with its options as the config (`eisenhower` → `eisenhowerSummary`; the tab's `detailsWidth` to `followup` / `stale` / `recent`). In a column: Number cells six to a fit row, a row of the list tiles' cells, then the sections packed into rows by their old spans (12 columns, a row's last stretched), a span the cell's width weight; the new weighted rows share the old row's weight (a section row one share, the list row a quarter), and replace the row when the Dashboard was its only tab in its row's only cell — else the cell keeps its other tabs (its active tab moving off the Dashboard to the next, else the one before), the row its other cells, and the new rows go below it, the kept row one share; a collapsed row's new rows are collapsed. In a band: each part a cell of the band's row (a Number 1, a list tile 2, a section its own span; scaled to the cell's weight when the band has other cells). A Dashboard with no parts just goes, and so does a cell, row, column or band left empty. Fresh ids `<tab>-n<i>` (tab), `<tab>-c<i>` (cell), `<tab>-r<i>` (row), `_2`, `_3`, … when taken at any level, so a draft's base upgrades to its stored layout's ids. It holds its own copies of the defaults, choices, spans and packing) and **v78** (`upgrades/v78/index.ts` — Dashboard building, D26: one step composing four transforms in order over `layouts` and kept layout drafts, each pure, idempotent and holding its own copies of what it reads. `layout-table` (P1): a layout's columns → rows → cells and bands become a table — its lines from v77's geometry (across: the column weights, inside a column each row's cells' weights, a band's cells across the whole width; down: each column's row weights between the bands, which become `px` tracks at the top and bottom keeping their ids; a fit row counts as a nominal 76px of an 800px column area, at most half of it together; positions within 1e-9 one line), the weighted tracks scaled to whole numbers summing to 1000 per axis (each at least 1), a row track collapsed when every cell over it came from a collapsed row or band, a bands-only layout's column area one empty cell; each cell keeps its id, tabs and active tab; `stripShown` and `activeColumnId` go; fresh track ids `grid-c<i>` / `grid-r<i>` (`_2`, `_3`, … when taken), so a draft's base upgrades to its stored layout's ids; a row with a `grid` already passes. `widget-set` (P4): an `eisenhowerSummary` tab becomes `{ kind: 'eisenhower', config: {} }` with its id, a tab of a removed kind (`followup`, `next7`, `stale`, `recent`, `changes`, `today`) goes, a cell left without tabs closes by the frozen copy of the absorb rule in `upgrades/layout-tabs` (`layoutTabsOf(row, step)`, shared with v79: the whole-edge neighbour, else the side's neighbours together, else an empty cell; in reading order), then the lines no cell's edge lies on merge (their sizes added). `numbers` (P5): a Number's `{ metric, breakdown? }` becomes `{ name, color?, filter, show: 'count', litWhen, litAt?, compare, breakdown? }` — the metric's label, its filter (`number-metrics`, import-free so the dev seed and tests share it: open none, `overdue`, `due today`, `due within 6 days`, `followup <= today`, `no followup`, `/focus`, `/urgent`, `completed this week`), its colour as the dark theme's hex (the accent's metrics Auto), `above` 0 for the metrics that lit, `lastWeek` for Closed this week. `breakdown` (P8): `people` / `tags` / `status` tabs become `breakdown` tabs with the same id — every open task, bars, counting, `showNone` from `showUnassigned` / `showUntagged` (else shown)) and **v79** (`upgrades/v79/index.ts` — the final shapes, widget feedback 2026-11-11 decision 6: two parts over the whole dataset, each pure, idempotent and holding its own copies. `layouts` (`layoutV79Of(row, ranges)` through `layoutTabsOf`): `eisenhower` / `tagMap` / `statusFlow` tabs go (an emptied cell closes, the active tab moves to the one before, else after); a Review tab's config becomes `{}` and its `currentId` / `skipped` go; a Breakdown without `columns` gets Due and Follow-up (ids `due` / `followup`) from its `badges` over the data's own `tabBadgeDue` / `tabBadgeFollowup` rows (`appRangesOf`: each its row, else 3 / 0; a kept draft has no settings rows, so the defaults), `badges` and `checkins` go, and each split's sort reads as `liveBreakdownSort` did (an older derived key to its column while it has it, else removed); a Number's config `ignoreLens: true` becomes `viewState.ignoreLens` unless the view state has a boolean already (it wins); a list tab's `strips` zoom becomes `lines`; Created vs completed gets `name: 'Created vs completed'` / `show: 'bars'` where absent (its `filter` stays absent: it reads as the empty filter); an emoji icon's `show: 'muted'` goes, on tabs and the layout; a layout's `lensId` goes. `leftovers`: a `listDefinitions` row owned `{ eisenhower: true }` goes with its `listOrders` rows — unless a layout row names its id (`listDefinitionId` anywhere), when it is kept without its owner —, `eisenhowerPanes` / `eisenhowerSource` go, a `rowDensity` of `strips` / `comfortable` / `compact` becomes `lines` / `stacked` / `rows`), **v80** (`upgrades/v80/index.ts` — check-ins by copy: every `people` row without `email`, the `checkinOpenMethod` settings row deleted; pure, idempotent, a table it leaves alone the same array) and **v81** (`upgrades/v81/index.ts` — lenses removed: the `lenses`, `activeLensId` and `lensPresetsSeeded` settings rows deleted, the `keyboardShortcuts` row without its `cycle-lens` / `lift-lens` bindings (a row that doesn't read left for validation), every `listDefinitions` row and every layout tab's view state without `ignoreLens`, a view state left empty removed; pure, idempotent, a table it leaves alone the same array); the header says what a schema step N adds — its transform `data/upgrades/v<N>-<what>.ts` registered as `[N, upgradeV<N>]`, the `this.version(N)` declaration, the `import-validation` `check*` / `pick*` changes, and its tests (the transform's own, the export → restore round trip, "v(N-1) reader refuses vN"). `upgradeDataSet(data, from, to, registry?)` applies `from+1 … to` in order (missing entry = identity;
