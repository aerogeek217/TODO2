`setPlan(ids, plan, description?, snackbar?)` / `setPlans([{ id, plan }], description?, snackbar?)` (a task's plan state in the Planner — `plan` a `TaskPlan`: `{ day }` (`doDate` at local midnight, `unplanned` removed), `'unplanned'` (`unplanned: true`, `doDate` removed) or `null` (neither); **both fields in the task's one write**, every task in one database write and one undo step — with the snackbar and its Undo only when `snackbar` is passed (Reset plan, Unplan all Delayed, a plan that takes the task out of view) —; **it never rejects**: a failed write is taken back with each task's two fields together and only where both still hold its values (`bulkUpdateTasks`' `together`), the tasks are read back, the user is told `Couldn't save the plan of “Title”.` and it resolves `false` (`true` otherwise); named `description` or `Planned “Title”` / `Unplanned “Title”` / `Cleared the plan of “Title”` / `Changed the plan of 3 tasks`; only the tasks whose plan changes are written; **it never stamps**: `bulkUpdateTasks` with `KEEP_STAMPS`, so the write, its undo and its redo — which put both fields back — leave each task's `modifiedAt` as it is, stored and shown, no history event is logged and no due date or follow-up is written),

### usePlannerStore, usePlannerWindow, plannerWindowKey, PlannerDragPreview — stores/planner-store.ts

Each Planner tab's window, in memory only (never layout config or view state; gone with a reload): `windows[key] = { offset }`, `key` = `plannerWindowKey(layoutId, tabId)` (the tab in its layout: Duplicate layout keeps the tabs' ids, and the copy's Planner has a window of its own; no layout open: the tab alone) — `offset` the days from today to the window's first day (a multiple of 7, 0 or more: `utils/planner.plannerOffset`); no day is picked (a tile's click scrolls). `shift(key, weeks)` moves the window a whole number of weeks (never before this week); `reset(key)` is back to this week; `keep(layoutId, tabIds)` drops that layout's windows whose tab isn't one of its Planner tabs now (a tab closed or changed to another kind starts on this week if it is a Planner again; the other layouts' stay). Kept in the store, not in the widget, so the widget popup's remount (a tab has one live widget at a time) shows the same week. `usePlannerWindow(key)`: that window (this week until it is moved). **`resets`** (`setReset(key, report | null)`): each drawn Planner's Reset plan report, by the same key — `{ counts, week, run }`: how many tasks each scope would clear, the first scope's name (`This week`, or the shown range while the window is shifted) and the action, which resets the Planner as it shows when called — written by the widget's own hook (`hooks/use-planner`, only when a count or the name changes; removed when the widget unmounts) and read by Reset plan's menus (`planner/planner-reset`), so no menu builds the view.
