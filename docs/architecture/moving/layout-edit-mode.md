### useWorkspaceStore, settleLayoutWrites, isLayoutEditStep, EditUndoOptions, layoutEditChanged, LayoutEditSession, listsHeldByEdit — stores/workspace-store.ts (part 2)

**The layout edit mode** (layout edit mode E1, `editing: LayoutEditSession | null` — `layoutId`, `selectedCellId`, the mode's own `undo` / `redo` stacks of bodies, `createdLists`, `showContent` — the mode bar's Content toggle, `setEditContent(on)`: the cards show their widgets dimmed instead of as blueprints): `enterEdit({ cellId? })` asks an open editor holding changes first (`afterLeavingEditors`' rule), lets the layout's writes land (a failed one retried; failing again, the mode doesn't open), closes every editor (`closeOpenEditors`), the widget popup, the filtered-tasks panel and the snackbar, and registers the mode as a **layout-wide** editor (`editor-leave`). While it is on `working` is the draft and `saved` the layout as stored: `edit()` puts the draft's body before each structural edit on the mode's undo stack (a merge key merges there too) instead of committing, and `editView` — so every resize, `endResize`, `setTrackSizes`, `copyTrackSizes`, `clearTrackFitPx`, an active tab, a collapse, a tab's view state — changes the draft only; nothing is written. `undoEdit` / `redoEdit` step its stack (the view state of now kept, `withViewStateOf`); `layoutEditChanged` is the draft ≠ stored, view state included (`layoutBodyEqual`). **Done** (`finishEdit`) deletes the lists the session made that the draft doesn't show, then commits the draft as one `commitEdit(saved, draft, 'Edited layout “X”')` — one write, one undo step whose Undo brings back the lists it dropped — when its structure changed, writes its view state alone when only that did, else just leaves. **Cancel** (`cancelEdit`) puts `saved` back and, with changes, notifies `Layout changes discarded` with **Restore** (the session and the draft back, the mode open again — while the layout is open and structurally as it was); the session's lists are deleted once that offer is gone (`undo-store` notice `onEnd`: timed out, dismissed or replaced); meanwhile `discardedLists` holds them, and `listsHeldByEdit(state)` — those plus, in the mode, the lists the session made that the draft no longer shows — is what no list chooser offers (`hooks/use-held-lists`: Copy from…, Follow a list). `discardEdit` (the leave question's Discard) / `leaveEdit` (no changes) delete them at once; `askLeaveEdit` asks Save / Discard / Keep editing (`ui-store.askChoice`, one question at a time); `dropEdit` closes it from outside where nothing asks (the workspace page gone, a phone's width), saying so when it held changes; `endEditForReplace` (`refresh-all`) closes it with a notice and drops a pending Restore without deleting (the ids may name other lists in the new data); `noteEditList` records a list `createListAndTab` made. **Move / Copy to layout** (2026-11-18): `transferTo(to, what, copy)` (`to` a layout id or `{ newName }` — `createLayout` first) leaves the open layout as `load` does (in the mode, `askLeaveEdit` first), reads what it carries from the layout as stored (`utils/layout-transfer.carriedTabs`), opens the target and begins a session with `incoming` (`IncomingTransfer`: copy or move, the source's id and name, its tab ids, the tabs as they land — an id the target uses renewed —, a cell's active tab, its name, `madeLayout`); `placeIncoming(target)` places them (`placeIncomingTabs`, an `edit()` step of the mode, the holding cell selected), and while they wait `tapEdit` places them in the tapped slot or card (`{ kind: 'place' }`); `edit()` lets the carried lists through `foreignListRefs`. `finishEdit` with them placed runs `finishTransfer`: the source re-read from the repository, the session's unshown lists pruned, `transferListPlan`, `layoutRepository.transfer`, both rows into the store (`takeStored`), the lists' stores reloaded, and one undo step (`TransferRun`: both bodies, `reown`, `copyIds`, the writes' removals) whose `undoTransfer` / `redoTransfer` write both layouts from either (each as stored now with the view state of now; `UndoRefused` in the mode, `UndoGone` once a layout is gone); a failed write keeps the mode open. `cancelEdit` while carrying discards the draft and loads the source again (deleting a layout made for it). Meanwhile layout undo / redo steps refuse (`UndoRefused`, `Finish editing the layout to undo: …`), and `rename`, `retryWrite`, `reorderLayouts` / `moveLayout` refuse (`Finish editing the layout first.`); `load`, `createLayout`, `duplicateLayout` and `delete` go through `editor-leave.leaveLayout` (the mode asks with changes, closes without). A reload or a closed tab drops the draft silently; the next launch's `init()` prune deletes the lists it made (a second browser tab's prune may delete one sooner — accepted).
