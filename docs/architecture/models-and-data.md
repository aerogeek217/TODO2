# Models & Data Layer

Detail reference for `src/models/` (TypeScript interfaces) and `src/data/` (Dexie persistence). Load when touching schema, repositories, migrations, import/export, or model shapes.

| TodoEvent, PersistedTodoEvent, TodoEventType | models/todo-event.ts | Append-only history log entry; nothing in the UI reads it — the rows travel with exports and task archives. Helpers: `clampRailSize` ([200, 600]), `defaultRailSize`, `railSize`, `railOrientationForSide`, `EMPTY_RAILS`, `CORNERS`, `serializeRailsState` / `parseRailsState` (`parseSlot` requires `tabs[]` + `activeTabId`; `parseTab` accepts only the array shape for `runtimeFilterValue`; round-trips `corners`, dropping unknown keys and non-`'h'|'v'` values; returns null on shape failure) |

## Data Layer

| Abstraction | Location | Purpose |
|-------------|----------|---------|
| Todo2Database | data/database.ts | Dexie DB class with schema versioning. The `.version(N).stores(…)` chain stays so Dexie can walk to the current schema. Most `.upgrade()` bodies are empty — legacy translators were stripped (strip-backcompat-pre-v46-2026-04-27) once `OLDEST_SUPPORTED_DB_VERSION` rose to `CURRENT_DB_VERSION`. The current exception is **v49** (fuzzy-schedule-aging-2026-05-09 P0): an idempotent backfill walks `todos` rows where `scheduledDate?.kind === 'fuzzy'` and `setAt` is unset, then stamps `setAt` from the most recent `'scheduled'` `todoEvents` timestamp (fallback `todo.createdAt`). Re-running v49 finds zero matches. Every data-shape bump wires its `.upgrade()` as `(tx) => applySchemaUpgradeInTx(tx, N)` so the live DB and imported files run the same registry transform. **v50** is the first: `upgradeV50` revives string-typed Date fields; **v51** `upgradeV51` backfills `uid` + `completedAt` and adds the `&uid` index; **v52** `upgradeV52` drops the `floatingHorizons` / `floatingScoreboard` / `floatingSnoozeGraveyard` tables (declared `null`) and cleans the matching settings; **v53** `upgradeV53` removes `scheduledDate` (no store change).
