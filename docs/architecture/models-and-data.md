# Models & Data Layer

Detail reference for `src/models/` (TypeScript interfaces) and `src/data/` (Dexie persistence). Load when touching schema, repositories, migrations, import/export, or model shapes.

## Data Layer

| Abstraction | Location | Purpose |
|-------------|----------|---------|
| Todo2Database | data/database.ts | Dexie DB class with schema versioning. Tables: `todos` (`++id, isCompleted, dueDate, sortOrder, statusId, &uid`), `people`, `settings`, `todoPeople`, `backups`, `statuses`, `listDefinitions`, `notes` (`++id, modifiedAt`), `tags`, `todoTags`, `todoEvents`, `layouts`, `listOrders`. The `.version(N).stores(…)` chain stays so Dexie can walk to the current schema. Upgrade bodies before v49 are empty (legacy translators were stripped once `OLDEST_SUPPORTED_DB_VERSION` was pinned). **v49** is the one hand-written upgrade: an idempotent backfill walks `todos` rows where `scheduledDate?.kind === 'fuzzy'` and `setAt` is unset, then stamps `setAt` from the most recent `'scheduled'` `todoEvents` timestamp (fallback `todo.createdAt`). From v50 on every version wires its `.upgrade()` as `(tx) => applySchemaUpgradeInTx(tx, N)` so the live DB and imported files run the same registry transform. **v50** `upgradeV50` revives string-typed Date fields; **v51** `upgradeV51` backfills `uid` + `completedAt` and adds the `&uid` index; **v52** `upgradeV52` drops the `floatingHorizons` / `floatingScoreboard` / `floatingSnoozeGraveyard` tables (declared `null`) and cleans the matching settings; **v53** `upgradeV53` removes `scheduledDate` (no store change); **v54** `upgradeV54` removes hide-by-status (no store change); **v55** `upgradeV55` merges orgs into people and drops the `orgs` / `todoOrgs` / `personOrgs` tables (declared `null`); **v56** `upgradeV56` adds the `layouts` table (`++id`) and seeds the Default layout; **v57** `upgradeV57` strips list `favorited` and saved list-tab prompt picks (no store change); **v58** adds the `listOrders` table (`++id, listDefinitionId, todoId, &[listDefinitionId+todoId]`) — no registry entry (an empty table = every task unranked); **v59** `upgradeV59` turns the taskboard into Focus and drops `taskboards` / `floatingTaskboards`; **v60** `upgradeV60` turns projects into tags and drops `projects` / `canvases` / `listInsets` / `floatingCalendars` / `floatingNotes` / `floatingStatus` (declared `null`), restating `todos` without the `projectId` / `canvasId` indexes and `notes` without its `canvasId` index; **v61** `upgradeV61` rewrites stored list predicates from `focus` to `markers` (no store change); **v62** `upgradeV62` drops every `status` tab from the stored layouts (no store change); **v63** `upgradeV63` drops `pinnedToDashboard` from list definitions and renames `color.*.canvasBg` to `color.*.appBg` (no store change). **v64** `upgradeV64` folds each stored list predicate's date range and presence filters into `dates` (a clause per date type) and drops `maxTasks` / `limitMode` and the `maxTags` setting (no store change). | CURRENT_DB_VERSION, OLDEST_SUPPORTED_DB_VERSION, DatabaseTooNewError, findDatabaseTooNew, tooNewDatabaseMessage | data/database.ts | Two source-of-truth schema constants. `CURRENT_DB_VERSION` (66) is the latest declared `.version(N)`; the `migration-check.test.ts` `db.verno` assertion guards bumps.
