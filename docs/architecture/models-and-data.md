# Models & Data Layer

Detail reference for `src/models/` (TypeScript interfaces) and `src/data/` (Dexie persistence). Load when touching schema, repositories, migrations, import/export, or model shapes.

## Models

## Data Layer

| Abstraction | Location | Purpose |
|-------------|----------|---------|
| Todo2Database | data/database.ts | Dexie DB class with schema versioning. Tables: `todos` (`++id, isCompleted, dueDate, sortOrder, statusId, &uid`), `people`, `settings`, `todoPeople`, `backups`, `statuses`, `listDefinitions`, `notes` (`++id, modifiedAt`), `tags`, `todoTags`, `todoEvents`, `layouts`, `listOrders` (`++id, listDefinitionId, todoId, &[listDefinitionId+todoId]`). **One declaration**: `this.version(OLDEST_SUPPORTED_DB_VERSION).stores(FLOOR_STORES).upgrade(refuseBelowFloor)` — the floor's whole store layout. Dexie 4 needs no declarations of the versions before it (opening a database it diffs the stores it finds against the declared ones and runs only the upgrades of versions above the database's own), so the floor's `.upgrade()` runs exactly for a database below the floor: `refuseBelowFloor` throws `DatabaseTooOldError`, which aborts the version-change transaction — IndexedDB rolls back every store / index change and the database keeps its old version, stores and rows. A schema step N declares `this.version(N).stores({ …only what N changes })` after it, its `.upgrade()` as `(tx) => applySchemaUpgradeInTx(tx, N)` (the same registry transform an import of an older file runs), and raises `CURRENT_DB_VERSION` |
| CURRENT_DB_VERSION, OLDEST_SUPPORTED_DB_VERSION, BELOW_FLOOR_BUILD, DatabaseTooNewError, DatabaseTooOldError, findDatabaseTooNew, findDatabaseTooOld, tooNewDatabaseMessage, tooOldDatabaseMessage | data/database.ts | Two source-of-truth schema constants. `CURRENT_DB_VERSION` (68) is the latest declared `.version(N)`; the `migration-check.test.ts` `db.verno` assertion guards bumps. A database whose stored version is above it (a newer build saved it) is never read or written: `services/migration-check.checkTooNewDB` says so before anything opens it, and the database's own open fails with `DatabaseTooNewError` (a sticky `ready` subscriber comparing with `verno` — Dexie would otherwise open it at its own version; `findDatabaseTooNew` finds it inside the errors of later calls). `OLDEST_SUPPORTED_DB_VERSION` is **pinned at 68** (a literal; raised from 49 on 2026-10-23, user-approved, when the v50–v68 upgrades were removed). A browser database below it is refused — `checkTooOldDB` before anything opens it, and the floor declaration's upgrade (`DatabaseTooOldError`, `findDatabaseTooOld`) as the backstop — and so is any file below it or without a version marker (`prepareImport`'s `too-old`): nothing read, nothing written, no way to go on. `tooOldDatabaseMessage` / `file-version.tooOldFileMessage` name the version found and `BELOW_FLOOR_BUILD` ("the last TODO2 build from before 2026-10-23" — the build that upgrades such data; tag `last-v49-upgrade-2026-10-23`).
