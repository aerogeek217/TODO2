# Components

Detail reference for `src/components/` (workspace, task, overlays, shared, layout, settings) and `src/views/`. Load when touching UI, workspace widgets, overlays, editors, or view-level wiring.

## Views

| Abstraction | Location | Purpose |
|-------------|----------|---------|
| ROUTE_WORKSPACE, ROUTE_SETTINGS, LEGACY_ROUTES, AppRoute | routes.ts | Route paths for the hash router. `App.tsx` renders `WorkspacePage` at `/` (`ROUTE_WORKSPACE`, inside an `ErrorBoundary` scoped "Workspace"); `/settings` renders the mobile `SettingsPage` on a phone and, on desktop, opens the Settings modal and redirects to `/` (a deep link); every former page route in `LEGACY_ROUTES` (`/workspace`, `/list`, `/calendar`, `/dashboard`) and any unknown path redirects (`<Navigate replace>`) to `/`. Imported by `App.tsx`, `BottomTabBar` and `TopBar` |
| Section / buildListSections / listSortComparator / truncateSections | services/list-sections.ts | The section builder behind every list widget. See the `architecture/services-and-utils.md` row for the full surface |
| WorkspacePage, useWorkspaceData, useTabDragState, UnsavedNavigationGuard | views/WorkspacePage.tsx | `/` — the app's main page. Renders `WorkspaceView` on desktop and `MobileWorkspaceView` on mobile (`useIsMobile`); on mobile the `DndContext` gets no sensors, so nothing drags. Calls `useWorkspaceStore.init()` on mount when not hydrated (pages mount after App's startup chain, so after the sync-file load). `useWorkspaceData` loads **all** tasks (`loadAll`), people, tags, statuses and list definitions, plus `useEntityAssignmentsForTodos(todos)` — so chips and person / tag groups render on a cold load. Owns the page `DndContext` (`buildTaskCollision`: tab drags match no droppables, everything else `pointerWithin`): tab drags (`active.data.type === 'workspace-tab'`) — on drag start the page measures the workspace (`measureWorkspace`), a window `pointermove` listener runs `hitTestWorkspace` → `dropTargetForHit` → `dropChangesLayout` (no-ops stay plain) into `TabDragContext`, and drop calls `moveTab`; Esc cancels. Task drags go through `dispatchTaskDrop` (calendar day; which date it sets: see `resolveCalendarDropType`; the write is `buildRescheduleUpdate` → `useTodoStore.update`) — its `chooseType` opens `CalendarDropChooser` (`useCalendarDropChoice`; the dropped-on day stays highlighted through `PendingCalendarDropContext`). Auto-scroll only scrolls a container while the pointer is inside it (`useAutoScrollUnderPointer`: dnd-kit otherwise scrolls the dragged row's list from another column). `DragOverlay` shows the tab ghost (+12/+10 from the pointer via a modifier, plus a "New column" pill on column-edge hits), a lifted calendar entry (`calendarEntry` drag data) or the task row (a ghost `TaskRow`, styled by `components/workspace/DragOverlayTask.module.css`). Hosts `TaskDialog`, `TaskEditPopupHost`, `DashboardListsEditor` (`ui-store.listsEditorOpen`), `StandaloneListEditor`, `ListOptionsHost`. `UnsavedNavigationGuard`: `useBlocker` (pathname changes while the layout is dirty or a list has unsaved edits) → `UnsavedPrompt` (Save → then proceed; Discard → then proceed; Cancel → reset) and a `beforeunload` prompt while anything is unsaved |

## Popover patterns

Every floating panel anchored to a click-coord or a trigger element routes positioning + dismissal through the shared `usePopoverAnchor` hook (`hooks/use-popover-anchor.ts` — see services-and-utils.md). The hook owns flip-on-clip + clamp + scroll/resize/Escape/outside-click; the caller owns the panel + its `createPortal` wrapper. Current consumers include `ListDefinitionPickerPopup`, `WidgetKindMenu`, `RuntimeFilterPicker`, `FollowupPopover`, the desktop `FilterChipBar` pickers and Filters menu, `StoragePill`, `MenuPopover`, `CalendarDayPopover`, `ListOptionsHost`, `PredicateFieldPicker`, `SwitchToManualPopover`, `StatusEditor` and `NotesNlpPopup` (a `rect` anchor at the notes caret).

**When to add a new popover, do this and only this:**

1. Choose an anchor: `{kind:'ref', ref}` for an element-anchored popover (panel tracks the trigger on scroll); `{kind:'point', x, y}` for click-coord popovers (right-click / contextmenu).
2. Call `usePopoverAnchor({ anchor, open, onClose })`. Defaults handle scroll-close / resize-close / Escape / outside-click.
3. Render the panel inside `createPortal(<div ref={panelRef} style={style}>…</div>, document.body)` — the hook is the *only* place that should compute panel position; consumers should not also write a separate clamp / flip `useEffect`.
4. For nested flyouts whose drop target sits outside the panel (e.g. `WidgetKindMenu`'s Change-list submenu), pass `extraInsideRefs: [flyoutRef]` so outside-click ignores them.
5. Ref-anchored popovers that should *reposition* on scroll instead of closing (`RuntimeFilterPicker`) pass `closeOnScroll: false, closeOnResize: false` — the hook's reposition mode kicks in for `kind: 'ref'` anchors, while `kind: 'point'` anchors stay static.
6. Popovers that own special Escape logic (e.g. `WidgetKindMenu`'s "close flyout first, then menu") pass `closeOnEscape: false` and keep their own keyboard handler on the panel.

**What NOT to do:**

- Do not write per-component `useEffect` for `getBoundingClientRect()` math, scroll listeners, resize listeners, or document-level `mousedown` / `keydown` outside-click handlers. Every one of those is folded into the hook.
- Do not portalize a popover from the *call site* (`createPortal(<MyPopover/>, body)` at the consumer). The popovers above portal *internally* — adding a wrapping portal at the call site double-portals harmlessly but obscures intent.

## DnD diagnostic flag (`?debug-dnd=1`)

Append `?debug-dnd=1` to the URL to log every guard branch and resolution path of the task drag-and-drop path (list widget, Eisenhower and dashboard rows and calendar entries dropped on calendar days and quadrants). When a drag silently misses (no console error, no visible feedback), flip the flag, redo the drag, and the console emits the ladder — collision rule chosen → resolved `over.id` → guard outcomes → final dispatch.

The flag is read once at module load via `utils/debug-flags.ts`; each call site uses the gated `dndLog(label, payload?)` helper so production console stays quiet when the flag is absent. This is **permanent diagnostic infrastructure** — the small bundle cost (a few dozen no-op string literals) buys real diagnose value.

**Wrap sites:**
- `utils/task-dnd/dispatch.ts` — every branch of `dispatchTaskDrop` (no-active-todo, calendar-day reschedule, calendar-day choice cancelled, Eisenhower drop with its result, unhandled).
- `utils/task-dnd/collision.ts` — `buildTaskCollision` rule selection (no-active fallback, rule matched with index + algorithm + droppable counts, no-rule-matched fallback).

Workspace tab drags and list-row reorders don't go through these (they hit-test measured geometry) and are not logged.
