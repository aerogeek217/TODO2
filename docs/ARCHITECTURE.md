# Architecture Overview

This file is the always-loaded orientation. For per-abstraction detail, load the relevant reference file under [Detail References](#detail-references).

## Tech Stack
- **Frontend**: React 19 + TypeScript, built with Vite
- **State**: Zustand stores
- **Database**: Dexie.js over IndexedDB (local-first)
- **Spatial Canvas**: React Flow
- **Drag-and-Drop**: dnd-kit
- **Routing**: React Router v7 data router (`createHashRouter` + `RouterProvider`; one splat route renders the shell's `<Routes>`, so `useBlocker` is available)

## Data Flow

1. **Startup**: Dexie opens IndexedDB → `useCanvasStore.ensureDefault()` → `fileStorageService.initialize()` reconnects the file handle and runs the load decision — nothing on either side changes until the user resolves any disagreement (conflict / older file / unreadable file → `SyncConflictDialog` / `FileUpgradeDialog` / paused banner; state in `services/file-sync-state.ts`). Settings loads theme + applies `data-theme` to `<html>`; user color overrides applied as inline styles. If `completedRetentionDays` is set, completed tasks past it (keyed on `TodoItem.completedAt`, `utils/completed-at.ts`) are **never purged silently**: `App.tsx` records their uids after the sync-file load and `StartupPurgePrompt` → `PurgeCompletedDialog` asks (Export & delete → task archive via `services/purge-completed` + `services/task-archive`; Delete; Not now = this launch only). `backupScheduler.start()` begins auto-snapshots.
2. **Normal use**: UI → Zustand stores → repository methods → Dexie. If file storage is syncing, Dexie hooks debounce-save to the JSON file; while paused or awaiting permission the same hooks only mark the browser dirty (`dirtySince`), which forces a conflict prompt on the next load. Cross-cutting capture rides `QuickAddBar` (`Ctrl+Space` / FAB / `command-registry.openQuickAdd`); the `TaskEditPopup` create modal is reachable via QuickAdd's Details handoff and the canvas right-click menu.
3. **Canvas**: Single canvas only; `ensureDefault()` creates/selects at startup.
4. **View switching**: Sidebar → React Router (canvas `/`, list, calendar, settings; mobile redirects canvas, calendar and unknown routes to the workspace; its bottom tab bar is Workspace / Filters / Settings). Saved lists (`ListDefinition`) render on the canvas as lens rail slots or list-inset floats; with no persisted rail layout and at least one list definition, `useDefaultRails` seeds a right-rail lens slot with no list picked.
5. **Person assignment**: Many-to-many via `todoPeople` join; `usePersonStore` caches `assignedPeopleMap`. A person's optional `color` fills their avatar / chip / group swatch (`NEUTRAL_PERSON_COLOR` when unset).
6. **List widgets**: a list tab runs its definition through `useBuiltList` with the top-bar (screen) filter composed in — narrowing clauses AND (strict, even on the same field), `showCompleted` ORs (`filter-store.composeScreenFilter`). Edits to the definition from a widget (filter chips, List options, switch to scroll) go to `list-draft-store`: every widget showing the list renders the draft and shows it unsaved until the header's save button writes it; `UnsavedPrompt` asks before a layout switch, leaving the workspace or closing the list's last widget would drop it. Prompt picks live in `list-widget-store` and are never saved. A manual list (sort `manual`) orders by its `listOrders` ranks (unranked tasks after, oldest first; grouped lists keep one rank per task, so each group shows its tasks in rank order); dragging a row writes the new rank immediately — never part of the draft — and dragging in a sorted list offers to switch to manual order, seeded from what the list shows.

## Testing

Two layers, picked by what's being verified:

- **vitest (`npm test`)** — unit + JSDOM under `src/test/**`. Authoritative for pure logic, models, repositories, store reducers, services, utilities, and rendering / event-handler dispatch that doesn't depend on real layout, focus, or async DOM timing. `e2e/**` is excluded from the vitest sweep. `vitest.config.ts` splits two projects: `isolated` — any test file calling `vi.mock` / `vi.doMock` (detected at config load), one fresh worker per file so module fakes can't leak; `shared` — every other file, `isolate: false` (one jsdom + module cache per worker, the bulk of the speed-up), with `src/test/setup-shared.ts` restoring at each file boundary what a fresh worker would give: every zustand store back to `getInitialState()` (a `vi.mock('zustand')` wrapper registers each store as it is created), the Dexie db deleted, Testing Library `cleanup()`, `<body>` / `<html>` attributes / storage / URL cleared, real timers, global + env stubs undone, `vi.spyOn` spies restored.
- **Playwright (`npm run test:e2e`)** — Chromium-only real-browser flows under `e2e/**`. Starts its own `npm run dev` on fixed port 5173 (the everyday dev server is 5180), `reuseExistingServer`, `trace: 'retain-on-failure'`, `fullyParallel` (each test has its own browser context, so tests within one spec spread across workers). Fixtures + CDP-trusted gestures live in `e2e/fixtures/seed.ts`. `/list` specs must use `page.goto('/#/list')` (hash routing). CI is out of scope.

**JSDOM is not authoritative** for: focus handoffs, `ResizeObserver`-driven layout, drag-and-drop hit-testing (rails / floats / taskboard / `data-rails-drop-id` / `data-tbp-entry` geometry), popover anchor placement and viewport flips, async-store-driven re-render timing, and canvas positional behavior. Those categories require a Playwright spec — JSDOM passing is not enough signal.

**Diagnosis vs. regression.** The Chrome DevTools MCP server (`mcp__chrome-devtools__*`) is a *spike* tool — drive an interaction live in real Chromium, capture state, then codify the regression in Playwright. See CLAUDE.md "Tools — Chrome DevTools MCP".

**Manual-testing seed.** `npm run seed:dev` (`scripts/dev-seed.ts`) writes a realistic v49 export with dates relative to the run day to `dev-data/seed-v49.json` (gitignored); Settings → Import JSON in the dev server then runs the full v49 → current upgrade. `src/test/data/dev-seed.test.ts` keeps it importable.
